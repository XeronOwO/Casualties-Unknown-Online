## The question

Does dune mode — a 1.0 addition that turns the scene sandy — change anything the host or a member must sync?

## Chain (read 2026-11-10)

- `reversing/release-1.0/Assembly-CSharp/DuneMode.cs:12-30` — `Awake` caches `DuneMaterial` and starts `ShuffleObjects`; `ShuffleObjects` re-collects `Object.FindObjectsByType<GameObject>` every 20 s; `Update` swaps four random objects' materials (SpriteRenderer, Image, TilemapRenderer, TextMeshProUGUI) to the dune material each frame; the object is `DontDestroyOnLoad`.
- Nothing in the file reads or writes gameplay state: no body, no item, no world generation, no save. The effect runs on the client that has it, over whatever objects that client renders — including CUO's remote clones and the mod's own uGUI.
- The 1.0 run settings are the switch (`WorldGeneration.runSettings`), and the settings already travel in the run row (`WorldRunStateMapper` → `run.json`), read in the earlier run-settings item.

## Verdict

No adapter change. The effect is presentation-only and local, exactly like the game's own screen effects; a member sees its own dune filter over its own rendering, and the host's world truth is untouched. No wire field, no sync, no save field.
