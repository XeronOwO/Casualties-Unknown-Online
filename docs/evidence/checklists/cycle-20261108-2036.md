# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: `native-console-is-unpoliced.md` §Design + §The chain (read 2026-11-08).
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — `docs/development/native-parity.md` — evidence: the chain quotes `LimbStateEventHandler` accept-first and the native console's `heal`.
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: the live reading runs in the acceptance batch below (Steam2 native heal).
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): no player gesture changed; the entry is the console verb's own line — evidence: no player gesture; the entry is the report frame the handler already receives.
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: `LimbStateEventHandler.Handle`, `CharacterEventMerges.ApplyLimbStateEvent`, `CharacterLimbMsg` fields.
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: the bound covers every limb field the event carries (dismembered, skin, muscle, infection); the console-command half is named in the ticket as the second lever.
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: the six unit facts + the live reading in the batch section.
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: host log line `refused {Reason}` + the live Steam2 heal.
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: the user's report and direction (2026-11-08): validate, don't accept wholesale.
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: one 60-line validator + a 5-value enum file; the handler unchanged in size.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build 0/0, focused 6/6, suite 6628/0, gates 831/0, format exit 0.


- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
