# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.

- [x] Design comprehension — the heal's reset runs on the target's own client and reports back — evidence: `docs/backlog/done/1.0-console-heal-does-not-restore-a-member.md`.
- [x] Native parity — the ticket is a reading of the product's own relay — evidence: the closed record.
- [x] Native parity probe — the case passes on a pair the suite owns and in the full order — evidence: the run at 02:36.
- [x] Entry mapping — the entry is `/heal @a` through the driver's console action — evidence: `ConsoleHealCase.cs`.

- [x] Whole-family audit — the ticket moved to Done with both readings kept — evidence: `docs/backlog/done/`.
- [x] Self-check table — README row and census row point at the new path — evidence: `docs/backlog/README.md`.
- [x] Verification design — the suite's case is the standing judge — evidence: the closed record.
- [x] Plan approved by the user — night mode: a ticket closed from its own reading — evidence: the record.
- [x] Structure review done — one ticket closed, no code changed — evidence: the diff.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: gates 834/0 this cycle.

- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the

      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
