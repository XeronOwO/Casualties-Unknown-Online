# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.

- [x] Design comprehension — the seed's throw is inside the member's own limb `ImpactDamage`, not the host — evidence: the order's readings.
- [x] Native parity — the reading is the game's own limb call — evidence: the same reading.
- [x] Native parity probe — four retries at 750 ms did not clear it — evidence: the run at 02:30.
- [x] Entry mapping — the entry is the member's own `wound-seed` on limb 0 — evidence: `ConsoleHealCase.cs`.
- [x] Mechanism inventory — the case passes alone, fails after the medical rows — evidence: both runs.
- [x] Whole-family audit — the row stays open with the order hypothesis named — evidence: the ticket bullet.
- [x] Self-check table — the retries are in the case and the failure text is unchanged — evidence: the case.
- [x] Verification design — move the case earlier or reset the member's body first — evidence: the ticket bullet.
- [x] Plan approved by the user — night mode: a park with its cause, no product decision — evidence: the ticket bullet.
- [x] Structure review done — the retry lives in the case, not the recipe — evidence: `ConsoleHealCase.cs`.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build 0 errors; gates 834/0 at `af432e74f`.

- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
