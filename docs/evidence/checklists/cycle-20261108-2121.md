# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: `done/native-console-is-unpoliced.md` §The push-back names the directed reply and the local-body write; this cycle only records the reading.
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — `docs/development/native-parity.md` — evidence: the host's record answers with the same `LimbStateEvent` shape; the member writes the limb fields `CloneLimbRenderer` maps.
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: batch `20261108-u2`: Steam2's native `heal` (local 100/100), the host's refusal and directed answer, the member's local-body write, then `skinHealth 0.102, muscleHealth 21.397`.
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): no player gesture changed; the entry is the path the ticket names — evidence: the refusal branch of the limb report; no gesture.
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: host log `[LimbEvent] sent the host's record back to 76561199526807662 (15 limbs).`; guest log `applied the host's record to the local body (15 limbs).` at 21:16:52.136.
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: the correction loop writes every limb field the report carries; the other native verbs stay host-originated facts.
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: §The push-back (read 2026-11-08) names the frame, the send and the local write.
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: the three log lines plus the limb read after the exchange.
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: the user's rule: the host must correct the guest after the periodic report.
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: no src change this cycle; the recorded classes stay under the ceiling.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: gates `831/0` on the frozen tree; no compiled change this cycle.


- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
