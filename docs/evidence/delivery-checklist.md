# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.

- [ ] Design comprehension — the removal path's contract is "finish the work after any one throw"
- [ ] Native parity — the clone's parent is destroyed by the game's own scene change before the removal
- [ ] Native parity probe — the deployed build's host log at a member leave carries the renderer's line
- [ ] Entry mapping — the leave enters through the driver and leaves through the host's renderer line
- [ ] Mechanism inventory — both destroy sites carried the unguarded parent; both fixed
- [ ] Whole-family audit — the fix landed in the same commit as the guard; no second shape remains in the file
- [ ] Self-check table — gates 834/0 and the language check clean this cycle
- [ ] Verification design — the row is the log pair at a removal, read on the deployed artefact
- [ ] Plan approved by the user — night mode: fix or file every finding with its reading
- [ ] Structure review done — the ticket moved to done with its reading; the index row moved to the Done section
- [ ] Build + dotnet format + dotnet test normative gates pass

- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
