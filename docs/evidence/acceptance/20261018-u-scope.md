## Deployed fixture

`CasualtiesUnknownOnline.AcceptanceItemRead.dll` — a batch-local mod whose source is
`fixture-mod/ItemReadMod.cs` and whose shell is `fixture-mod/Plugin.cs`, compiled against this tree's
Abstractions build output (`fixture-build.log`). It declares `ReadGameState | RegisterCommand`,
`NetworkMode.Synchronized`, and registers `/idread <instanceId>`, which answers with
`IModGameState.TryGetItem`'s verdict (location, owner, limb, condition, favourited). Why: the deployed example
mod declares no `ReadGameState` and never calls `TryGetItem`, so without a fixture the ticket's "a mod that
recorded the id still finds it" row would have no mod that reads. It was placed in the physical plugins tree
(all three clients read it), its `/idread` command was smoked on every client before the rows (`prelude-*`),
and it was removed at the close (the plugins tree lists only the PinyinSearch pair again).

A **declared substitution**: the fixture is the batch's own mod, not the example mod; the read is the public
mod surface called from the deployed mod's own `IModContext.GameState`.
