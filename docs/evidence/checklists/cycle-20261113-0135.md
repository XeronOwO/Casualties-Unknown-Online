# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.

- [x] Design comprehension — the world census reads the host's own generated world; no design changed — evidence: `world-object-census` returned `total 1977` grouped by prefab.
- [x] Native parity — no native behaviour changed — evidence: the case only reads the game's own census.
- [x] Native parity probe — the case ran alone and inside the full suite — evidence: `world-census PASS` twice.
- [x] Entry mapping — the world domain's entry is the host's own generated world — evidence: the census recipe's own groups.
- [x] Mechanism inventory — one reading per case, named in the report — evidence: `.acceptance/suite/report.md`.
- [x] Whole-family audit — the new case plus the console-heal recurrence were both read this cycle — evidence: the report's `console-heal` section and the parked comment.
- [x] Self-check table — the ticket records both readings — evidence: the two bullets appended to `1.0-acceptance-suite.md`.
- [x] Verification design — one recipe call, judged on `total ≥ 1` — evidence: the case's assertion.
- [x] Plan approved by the user — night mode: a new case and a parking, no product decision — evidence: the ticket bullets.
- [x] Structure review done — the case is a small class beside the others, using the shared context — evidence: `Cases/WorldCensusCase.cs`.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build 0 errors this cycle; gates 834/0 at `e223ffbbb`.

- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
