# The restore cancels its own wait when the world is generated under it

- Status: Todo
- Priority: High
- Opened: 2026-11-25
- Owner: night run

## The reading

`.acceptance/reds-2` ran `save-continue` on the release install (`0.1.0+38016a31f`) and the row failed with
`the restore did not apply the 102 geyser types the live world held before the save`. The host's own dated log
(`BepInEx/logs/latest.log`) says what the row's message cannot:

```
06:08:40.001  World join sent to 1 member(s) (tutorial: False, run 4, baseline follows: True).
06:08:40.084  [GenStream] segment 15 … stage=<WorldGenerateStructures>
06:08:42.212  [GenStream] segment 16 … stage=<Wrap>
06:08:43.256  [SaveFacts] cancelled the pending restored native values — world facts (33 keypad code(s), 102 geyser type(…
06:08:43.256  [ERR] [SaveFacts] the live world did NOT take every restored fact (… 4 geyser type(s) applied …)
```

The restore was not merely short of time: it was **cancelled** while the layer was still generating (the
generation stream is at segment 15–16 of the same second), and the replay then ran against a world that did not
yet hold the geysers — four applied, ninety-eight refused.

## Why the wait did not save it

`RestoredWorldFactReplay` holds the restore while `GeyserFillWait.Holds(live, saved, stable, elapsed)` is true
(`RestoredWorldFactReplay.cs:185`), and that wait is bounded by the archive-scaled ceiling (30 s + 0.1 s per row,
hard cap 60 s). A cancel is a different event: it discards the pending values, so no ceiling can help.

## What to read next

1. Who cancels: the cancel line is logged by `NativeWorldFacts`; read its caller and the condition it acts on
   (a second restore, a fresh run, a generation restart).
2. Whether the cancel is right: a world regenerated under a pending restore cannot take the values, so the
   cancel may be the honest answer — in which case the row has to restore into a world that is already generated,
   or the restore has to be re-armed once generation ends.
3. Which of those two the product wants, and what the row then judges.

## Design

`docs/design/cross-cutting/saves-and-recovery.md` — the restore applies the archive's world facts onto the live
world; it does not regenerate the world to suit them.
