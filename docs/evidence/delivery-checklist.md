# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle.

- [ ] Design comprehension — the borders stage and its draw count were read
- [ ] Native parity — the size fields are the game own
- [ ] Native parity probe — the chip facts were identical, so the borders stage is the next suspect
- [ ] Entry mapping — the size is logged with every segment line
- [ ] Mechanism inventory — the borders draw per row per column per side
- [ ] Whole-family audit — one helper extended by two fields
- [ ] Self-check table — diagnostics only
- [ ] Verification design — the next failing run reads h and w on both clients
- [ ] Plan approved by the user — root cause first
- [ ] Structure review done — the probe stays in the isolation
- [ ] Build + dotnet format + dotnet test normative gates pass

- [ ] Release-cycle deployment/acceptance: deploy and read the size on a failing run

- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
