# 1.0 endings: the final layer's ending is the host's state

- Status: In progress — the run row carries the ending (`RunState.Ending`), the host's branch is recorded by
  the two ending patches, the projection stamps it into the advance and the save, and a member returns the
  host's enumerator instead of its own (commit `5d…`; gates 834/0). The live two-client reading is owed: a
  host ending recorded on the run, the member playing the same branch, and the save's `run.json` carrying
  the kind.
- Priority: High
- Category: World / release
- Source: the 1.0 map, `docs/design/game/worldgen-and-layers.md` and `docs/design/game/console-and-save.md`.

## The question

When a run reaches the bottom layer and the exit condition is met, does every client see the hosting
player's ending, or can two clients disagree about how the run ended?

## Chain (read 2026-11-09)

1. The exit runs when `biomeDepth == 10` and the body is above `halfHeight - 5f`
   (`reversing/release-1.0/Assembly-CSharp/WorldGeneration.cs:1205`).
2. The game picks between two endings: `MercEnding()` when the host carries the merchant's scarf, else
   `SurfaceBreachCutscene()`; both end with `RegenerateWorld(false)` — a new run, not a return to the menu.
3. The layer-advance event already travels as `RunAdvancedEvent` inside the item kernel batch (the
   layer-end cut trigger, `WorldSaveService.cs:500`), so the host's advance is on the wire.
4. The ending choice itself is not a wire field today: nothing in `CharacterLimbMsg`, the run row or the
   layer-advance event names it. A member runs its own `WorldGeneration` and can only follow the host's
   advance, not the ending branch.

## Design

The ending is a property of the run, decided by the host and recorded like every other authoritative run
fact: a field on the layer-advance event (or the run row) carrying the ending kind (`SurfaceBreach`,
`Merc`), set where the host's `WorldGeneration` resolves it; the member's client reads it and plays that
branch instead of its own resolution. If the host's ending is not yet on the wire when the member reaches
the edge, the member follows the host's advance and the ending is read from the event before its own
branch runs.

## Design (read 2026-11-10)

The ending is a property of the run, decided by the host and recorded like every other authoritative run
fact: `RunState` (`src/CasualtiesUnknownOnline.GameState/Domains/World/RunState.cs`) gains
`RunEnding Ending = RunEnding.None` (a new enum: `None`, `SurfaceBreach`, `Merc`). The run row already
travels twice — inside `RunStartedEvent`/`RunAdvancedEvent` and in the save's `run.json` — so the ending
reaches every client and the cut with no new message.

How the host's branch becomes the run's ending (the chain read this round):

1. The host's body reaches the exit; the game itself calls `MercEnding()` or `SurfaceBreachCutscene()`
   (`reversing/release-1.0/Assembly-CSharp/WorldGeneration.cs:1205`) and then `RegenerateWorld(false)`.
2. New adapter patch `WorldGenerationEndingPatch` (prefix on both ending methods): records the kind in a
   small `RunEndingTracker` (a static, host-only value; the member's side reads it, never writes it).
3. `WorldRunProjection.CommitBaseline` (`src/CasualtiesUnknownOnline.Runtime/Session/World/WorldRunProjection.cs:35-59`)
   stamps the tracker's kind into the `RunState` it hands `TryAdvanceLayer` — the advance event that follows
   the ending therefore carries it, and the save's run row too.
4. The member's client: the same prefix on the two ending methods checks the kernel run's `Ending`; when it
   is not `None` it runs the host's branch locally (the same method) instead of resolving its own; when it
   is still `None` the member waits for the host's advance (the event arrives before the member's own edge
   in the ordinary flow) and then plays the recorded branch.

Read so far:
- `RunState`, `RunAdvancedEvent`, `WorldDomainModule.DecideAdvanceLayer` (`WorldDomainModule.cs:98-112`), `AdvanceLayerCommand`.
- `KernelDomainCommands.TryAdvanceLayer` (`KernelDomainCommands.cs:41-51`) and its only caller `WorldRunProjection.CommitBaseline` (`:35-59`).
- The projection's apply (`WorldRunProjection.cs:69`) and the wire mapping (`KernelWireMapper.cs:334`).
- The member's follow (`DescentFollowController.cs:96-97`).
- `WorldRunStateMapper.ToRunState` builds the run state from `WorldStartParams` — the ending is NOT a start parameter; it is stamped at the advance.

## Acceptance

1. A run driven to the bottom layer on the host ends with one ending named in the host's log and in the
   layer-advance event.
2. The member's client shows the same ending (its log line names the same branch, or its state carries the
   same ending kind).
3. A member that reaches the edge first does not pick a different ending: its branch waits for the
   host's.
