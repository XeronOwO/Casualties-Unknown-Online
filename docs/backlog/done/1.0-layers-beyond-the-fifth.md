## The question

The release adds layers beyond the fifth (and an endless setting). Does the adapter assume a finite, small layer count anywhere — a cap, a table, a hardcoded depth — that would break the cut, the layer advance or the ending?

## Chain (read 2026-11-10)

- The game's own count is data: `WorldGeneration.amountOfLayers = temperatureCurves.Length` (`reversing/release-1.0/Assembly-CSharp/WorldGeneration.cs:128`), the curves being serialized scene data (`:5667`), and the descent/exit comparisons read `biomeDepth` against it (`:1432`, `:5252-5254`).
- The adapter reads the depth through reflection and passes it on: `HarmonyTraverse.ReadBiomeDepth`/`WriteBiomeDepth` (`HarmonyTraverse.cs:164-166`), `StartGateCoordinator` (a session starting at depth 0), `LayerAdvanceCoordinator` (writes `deepestlayer`, drives the game's own regenerate), `WorldParamsService`/`KernelDomainWireMapper` (the run row's `BiomeDepth`/`LayerIndex`).
- The layer-end cut keys on the kernel's `RunAdvancedEvent` (`WorldSaveService.cs`, earlier item), not on a depth constant; the ending keys on `biomeDepth == 10` inside the game's own method (the endings item), and the adapter forwards whichever native ending the host resolves.
- Nothing in `src/` hardcodes a layer count: a search for `amountOfLayers`/`biomeDepth` finds reads and writes of the live value only.

## Verdict

No adapter change. Layers beyond the fifth, and the endless setting, travel through the same run-row and cut machinery as the first five; the only depth-specific rule is the game's own ending at its final layer, which the endings item already carries.

## Acceptance

1. The chain above names every place the adapter touches the depth — reads, writes, the cut trigger and the ending.
2. The verdict (no cap, no change) rests on those lines; no live run to layer six was needed because no adapter rule branches on the number.
