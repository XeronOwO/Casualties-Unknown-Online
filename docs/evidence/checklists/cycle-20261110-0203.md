# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.

- [x] Design comprehension — evidence: the layers ticket cites the generator's own count and the adapter's depth reads
- [x] Native parity — evidence: n/a, a reading; no code changed
- [x] Native parity probe — evidence: n/a, no native chain touched
- [x] Entry mapping — evidence: no player gesture; the depth travels through the run row
- [x] Mechanism inventory — evidence: every adapter touch of the depth is listed in the ticket's chain
- [x] Whole-family audit — evidence: a search for amountOfLayers/biomeDepth shows reads and writes only, no constant
- [x] Self-check table — evidence: the ticket's §Chain + §Verdict
- [x] Verification design — evidence: the reading is the cited lines; gates 834/0 after the ticket/index/census edits
- [x] Plan approved by the user — evidence: the night split lists "layers 6-11" as its own item
- [x] Structure review done — evidence: no structure change; the ticket records the verdict
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: docs-only cycle, gates 834/0

- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
