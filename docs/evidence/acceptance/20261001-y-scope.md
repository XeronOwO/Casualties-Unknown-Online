## The evidence channel (declared before the run)

- **machine**: one recipe JSON per invocation under the local artifact directory, the three clients'
  BepInEx logs (the host's install and each shadow), and the deployed artifact identity.
- **visual**: window-level captures read by the agent; the drop rows additionally use the recorded
  crop-and-zoom of the same window frame — the game resets `Camera.main.orthographicSize` to 22.5 every
  frame, so the frame is what a run can magnify, not the camera.
- **feel**: the drop-motion row gets a frame sequence; what stays subjective is a residual.
- **timestamps**: the host's break lines and the peer's materialization lines carry the same machine
  clock, which is what separates "delivered by the break message" from "delivered by the 5-30 s keyframe".

## Session structure

1. **World + arm**: host creates the lobby, both sandbox clients join, host starts the run; `item-floating
   value=1` on all three; baseline frames.
2. **Drop family** (plan rows 1-2): one jump pad destroyed by the host while both peers watch; then one
   destroyed by the guest while the host and the third client watch.
3. **Crush family** (plan rows 3-4): the host's crush, then the guest's; log counting for the volume and
   the no-echo rows.
4. **Capacity family** (plan rows 5-6): the guest's own fill and the pump's refusal half, then the host's
   fill, the censuses, and the late joiner's delivery.
5. **Layer descent last** (plan row 7): `skiplayer` replaces the world; nothing after it needs the old one.

## Limits (declared before the run)

- One session is not a race proof; each row is read from the state the ends converge to.
- The late-joiner row plans the host's re-entry as the delivery path when a lobby rejoin does not
  re-activate the session (batch `20261001-x`'s rejoin wedge), and it is judged on the reads taken after
  that delivery.
- Visual rows are read from crop-zoomed window frames; a judgement that stays subjective is a residual
  for the user, never a self-issued pass.
- The crush needs a 1-health three-wide band inside `crush-find`'s radius, and a candidate is necessary
  but not sufficient (`Body.cs:2702-2712` also needs the body grounded and `standingOn.health <= 1f`): a
  run that cannot confirm the roll records the census and leaves the row `unproven` rather than guessing.
- No row of the swallowed-report family is judged here, and none is replaced by a weaker check.
