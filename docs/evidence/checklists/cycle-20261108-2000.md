# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: `trap-layout-crystal-rows-empty.md` §Fixture capability (2026-11-08) + §Batch 20261108.
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — `docs/development/native-parity.md` — evidence: `CrystalBehaviour.cs:60-140` (the effects list and `SetUpEffects`) + `TrapEntityScan.cs:138-172` (`CrystalKinds` maps the effect names).
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: no product behaviour changed this cycle; the reading ran the game's own scanner on a live crystal (`crystal-fixture` → `Kind=CrystalFragileBroken`).
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): no player gesture changed; the entry is the console verb's own line — evidence: the entry is the recipe's reflection call; no player-facing entry touched.
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: `TrapEntityScan.Scan:67`, `CrystalKinds:138`, `CrystalEffectAccess.EffectTypeNames`, `TrapLayoutEntryMsg`.
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: the scanner's 21 rows; the crystal row was the only one without a live probe, now read.
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: the ticket's §Batch 20261108 table (scan count 242 → 243; one crystal row).
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: the recipe returns the scanned row by reflection; the ticket carries the reading.
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: (user, 2026-11-08, translated) "keep pushing the next ticket, finish a whole ticket in one go".
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: no `src/` change; the new recipe is one file.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: gates `831/0`; no compiled C# changed (docs + acceptance recipe only), so build/format are not applicable.


- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
