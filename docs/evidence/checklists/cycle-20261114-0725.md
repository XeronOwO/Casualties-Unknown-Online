# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.
- [x] Design comprehension — the reset's own frame is the only place a healthy limb proves the write — evidence: the new `member-limb-at-reset` read
- [x] Native parity — no product content; the case reads the member's own body — evidence: the reading below
- [x] Native parity probe — three runs read `skinHealth 100, bleedAmount 0, pain 0, muscleHealth 100` at the reset — evidence: `member-limb-at-reset` in each report
- [x] Entry mapping — one entry, `/heal @a` on the host — evidence: `console-answer`
- [x] Mechanism inventory — a healthy immediate read means the flake is a run where the reset never lands, not a returning wound — evidence: the three reports against the earlier failing limb read
- [x] Whole-family audit — no other case reads the same frame — evidence: the diff
- [x] Self-check table — one test file changed — evidence: `git status --porcelain`
- [x] Verification design — three consecutive runs with the immediate read — evidence: runs 1-3 at 07:24
- [x] Plan approved by the user — the goal's main line — evidence: the 2026-11-14 paragraph
- [x] Structure review done — the read sits between the wait and the poll — evidence: the diff
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build 0 errors at 07:22; a test-only slice leaves the unit and gate suites unchanged

- [ ] Release-cycle deployment/acceptance: nothing deployed this cycle

- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
