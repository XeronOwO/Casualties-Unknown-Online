## Setups the scenario needs

- **The world**: the host creates the lobby, the guest and the third client join it, the host starts the
  run; all three read `inWorld: true` before anything is driven.
- **The patient's limb**: the guest seeds live shrapnel into limb 1 (`seed-shrapnel limb=1 count=3`). Limb
  and count are explicit — the recipe refuses to guess either — and the seeded count reaches the peers on
  the next character report, so the session starts after that report.
- **Line of sight**: the family's own gate refused a driven slip in batch `20261011-a` until both clients
  stood at one point, so both bodies are placed at a single spot (`body-place`, integer coordinates) and
  the operator's own client is the one that has to see the patient.
- **The native panel**: every remote-view drive opens the native `WoundView` inside the same call
  (`grip-slip-drive mode=open`, `remote-wound-special`), because the coordinator's pump tears a remote
  focus down while the native panel is closed and that teardown cancels the in-flight session.
  **Corrected 2026-10-11 by batch `20261011-c`**: the teardown this rule described was the drive's own
  doing — those recipes built the focus by hand from the peer's live render clone, and the focus's teardown
  then destroyed that clone. Production opens the view through `RemoteMedicalCoordinator.Open`; the recipes
  now do the same and the batch-`c` lessons carry the mechanism (`docs/acceptance/lessons.md`).
- **Start and break are two calls**: the ack that assigns the operation id is asynchronous (the host parks
  the start request and asks the target's client first), and `Open` must not be re-run for the break — it
  calls `Close`, and `Close` cancels the session the break belongs to.
- **The Stage-3 regression**: the guest's limb **2** is given a splint (`seed-splint limb=2`) and the host
  drives the removal through the native WoundView special action (`remote-wound-special target=<guest>
  limb=2`). Limb 2 is a different limb from the seeded shrapnel on purpose: the special action dispatches
  by the limb's own state, and a limb that carries shrapnel would start the shrapnel session instead. The
  splint is placed by the game's own application shape (the component, the item's condition,
  `conditionLossMinute`, `item = "splint"`) as a **declared setup substitution**; the removal under test
  is the native one.

Row 4's criterion is stated so it cannot be widened or narrowed after the fact: the removal's own outcome
has to land on the **target's own body** (the limb's splint flag cleared and the limb's `SplintLimb`
component gone) **and** still be there in the authority's copy at the next report. The row's stated
failure mode is a sentinel regression in the family, and a removal whose effect is restored by the
target's own report is the same class of failure the ticket itself is about: the target's report is the
authority's input for a guest body.

**Where the run did not meet a criterion as written**: row 1's probe read landed 5.75 s after the slip, not
inside the one-second window this page declares. The record states that plainly and judges the row on the
values (frozen while the limb carries fragments) plus the patient's own log line 414 ms after the authority
committed; no criterion was widened after the fact.
