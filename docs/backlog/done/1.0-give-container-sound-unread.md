# The give's container half: the backpack clip when the item lands in a container

- Status: Done (2026-11-19) — the clip was not playing; the container move ran through CUO's own intent
  (`ContainerIntentApplier.MoveInto`) instead of the drag, so the game's own call never ran. It now plays on the client
  that performs the move; the focused row reads it.
- Priority: Low
- Category: Cross-player item transfer / native parity (audio)
- Source: the 2026-10-25 report (translated): "why is there no sound when I move an item into another player's backpack?
  A normal item move has a cloth-rustle sound", and the later ruling of the same day: the give must not add the container
  sound where the game makes none — only the placement click belongs there.

## What the native rule says

`Body.PickUpItem` (`reversing/release-1.0.2/Assembly-CSharp/Body.cs:1467-1483`) plays
`PlayerCamera.main.PlayBackpackSound()` when the moved item leaves a container, and `PlayerCamera.cs:1748`, `:1828` and
`:1855` play it from the drag's own container branches. A body-slot give is silent by that same rule (measured
2026-11-19: neither client played a clip for a body-slot give, and the giver's apply branch already carries that ruling).

## Root cause of the container half

The container half was silent for a different reason: the give's item is loaded on the receiver's client by CUO's own
container intent, not by the game's drag. The measured chain is
`RemoteDragIntentDispatcher.ReportLocalReleaseOntoProxy` → `PlayerRemoteInventoryIntentService.Handle` →
`RemotePlacementService.BeginGive`/`Commit` → `PlayerInventoryTakeService.HandleRemoteGiveToBody` →
`PublishTransfer(PlayerInventoryTransferMsg)` → `PlayerInteractionApply.OnPlayerInventoryTransfer` →
`RemoteIntentApplier.ApplyPickUpToSlot` → `ContainerIntentApplier.MoveInto`. The native sound call sits on the drag branch
that this path bypasses, so nothing played.

The first fix attempt played the clip only in `PlayerInventoryPlacement` (the placement-side container seams) and the row
stayed silent (`.acceptance/give-container3`: host `raw=222|`, member `raw=207|`) — the give never reaches that class.

## Fix

`src/CasualtiesUnknownOnline.GameAdapter/Items/ContainerMoveFeedback.cs` makes the single
`PlayerCamera.PlayBackpackSound` call, once per frame (a gesture can reach two seams on the same client). It is called
where a container accepted the move: `ContainerIntentApplier.MoveInto` (after the native guard) and `MoveChildren` (once
when at least one child landed), and `PlayerInventoryPlacement` at its two container-load seams. A body-slot arrival stays
silent by the native rule, as before.

## Residual

- The clip can be heard twice for one gesture: the recording shows two entries at the same play time, because the
  placement seam and the intent seam both run on the receiver. `ContainerMoveFeedback` collapses calls in the same frame;
  the two that remain land in adjacent frames. One gesture should be one clip — named here rather than guessed at.
