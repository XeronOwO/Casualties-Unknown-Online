# A teammate can feed you without asking

Cross-player item use is started by the operator and applied on the target's own client
(`PlayerItemUseExecution`, the hand-feed arrangement in `NativeSolidFoodEat`). There is no step where
the target agrees, so an operator can force food, medicine or a dressing onto a teammate who may not
want it — including while the target is asleep (decision 270 lets a sleeping teammate be a valid
target for every cross-player item use).

## Design

The permission surface (`docs/design/cross-cutting/permissions-and-commands.md`) and the item-use
families that accept a body (`docs/design/items/README.md`; the families are classified in
`src/CasualtiesUnknownOnline.Runtime/Session/PlayerInteraction/ItemUseFamily.cs`). Consent is a
permission of the TARGET, not of the operator, so it belongs beside the host rules that already gate
remote access rather than inside a family.

## The reading (2026-11-14, release build)

`grep Consent src/` finds only comments; the target-side gate
(`src/CasualtiesUnknownOnline.Runtime/Session/PlayerInteraction/ItemUseTargetPolicy.cs`) decides
consciousness and sleep, not agreement. The reference mod ships this as a host rule
(`ConsentForFeeding`), which is the same shape our `RemoteBackpackAccess` rule already uses.

## What must be decided

Whether consent is a host rule with the reference's default (ask only for a CONSCIOUS target, act
freely on an unconscious one — the emergency case), or an unconditional prompt per target; and what
the operator sees while the target has not answered (a pending state, not a silent failure).

## Acceptance rows

1. With consent on, an operator's feed against a conscious teammate reaches the target's client only
   after the target agrees; while pending the operator sees "waiting for consent", and a refusal
   reaches the operator by name.
2. An unconscious target is fed without a prompt (the emergency default), named in the reading.
3. A host rule can turn consent off, and the ordinary feed then behaves as today.
