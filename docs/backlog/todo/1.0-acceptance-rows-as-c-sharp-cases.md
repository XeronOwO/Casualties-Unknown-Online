## What "C# acceptance" means here

- A row is a class under `tests/CasualtiesUnknownOnline.AcceptanceSuite/Cases/` registered in `CaseRegistry.All`; it
  drives the game through the in-process channel and asserts on readings.
- A recipe is the in-process primitive a case calls — C# deployed into the acceptance assembly, never a script the case
  shells out to. Recipes stay as primitives; the acceptance code is the case.

## The scripts — why each stays PowerShell

Each script is process machinery around the run, not a row; no row logic lives in one (checked 2026-11-19 by reading
each file's entry and by the suite's own report: the rows are C# cases, the recipes C# primitives):

| script | what it does | why it is not C# |
|---|---|---|
| `preflight.ps1` | reads the machine's state: deploy identity, Steam, sandbox, listeners, logs | it is a machine check before any process exists; nothing to drive in-process |
| `run-suite.ps1` | builds the suite, launches or restarts the pair, runs the exe, writes the report | it starts and stops OS processes and owns the run's artifacts |
| `launch-clients.ps1` | starts and stops host, guest and alt clients | process lifecycle, sandbox launch | 
| `drive-in-process.ps1` | one driver action from the shell for manual probes | a debug door; the suite talks to the same ws endpoint directly |
| `capture-window.ps1` | captures a window's pixels through `PrintWindow` | pixels are outside the process; a row reads `capture-frame` instead |
| `send-input.ps1` | stages real OS mouse/keyboard input | only OS-level input reaches the game's focus path; used per batch with authorization |
| `session-environment.ps1` | classifies a BepInEx tree, refuses while a game runs | machine bookkeeping before the game starts |

The suite's rows use the in-process driver's recipes (`virtual-input`, `capture-frame`) rather than the two OS-level
scripts, so a run needs neither unless the batch is explicitly the input batch.
