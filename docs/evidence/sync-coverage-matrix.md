# Sync Coverage Matrix — event sync + periodic fallback

- Status: Evidence — every synced surface's event + fallback policy, one bounded row each
- Produced by `docs/backlog/done/sync-event-and-periodic-fallback-coverage-audit.md` (audit date 2026-09-09);
  rewritten to bounded rows by `docs/backlog/done/document-corpus-audit.md`
- Scope: **A** kernel domains, **B** direct `NetMsg` families, **C** GameAdapter/Runtime sync
  surfaces, **D** adaptive streams
- Verdict vocabulary: `OK` | `Event-only gap` | `Fallback-only gap` | `Transient-by-design`

## Method

1. **S1 — freeze the inventory.** The row list was derived from the kernel domain table
   (`docs/architecture/domains.md`), the direct `NetMsg` classification
   (`docs/evidence/selfchecks/architecture/phase-e-legacy-inventory-selfcheck.md`), and every member of
   `NetMsg`, `WireCommandKind`, `WireEventKind` and `AdaptiveStreamId`. No row was dropped without a reason.
2. **S2 — evidence collection.** Per-row evidence — trigger message and numeric id, direction, reliability,
   fallback cadence, apply semantics, backfill path, loss semantics and source references — lives in
   `docs/evidence/sync-coverage-evidence.json`, keyed by row id, and every reference was mechanically
   verified against the working tree. `SyncCoverageGateTests` re-runs that verification on every
   `dotnet test`, so rotted evidence fails the gate instead of silently rotting. A reference is a path plus
   the quoted text and carries no line number: a line number drifts with every edit above it, while the
   quoted text is the claim.
3. **S3 — adjudication.** Every row got exactly one verdict. Four collector verdicts changed on
   adjudication (N6/N7/N8/R7 → `Transient-by-design` because the loss is accepted by design, F4 → `OK`
   because a continuous field has no discrete trigger) and, after the independent adversarial review, three
   more (W2/W6/I5 → `Event-only gap` because their own loss text admitted a non-convergent direction). All
   three have since landed, so they read `OK` now with their closing record in the last cell.
4. **S4 — gaps, guard, docs.** Every gap got an independent ticket, the rot guard landed, and the active
   docs that contradicted the matrix were corrected (see *Historical notes*).
5. **S5 — the bounded rewrite (2026-10-13).** Each row was read cell by cell and rewritten to state the
   policy as it stands, with the file paths, line numbers and cycle narrative removed and one pointer kept
   to the record that carries the closing detail. The verdict, the anchor count and the row id are
   unchanged, so the gate's contract is untouched.

carrier and reliability, its periodic fallback, its backfill/recovery path, what a loss costs, its verdict,
the number of evidence anchors it owns and the record that carries its closing detail. A row names no file
path and no line number: the quoted sources live in `docs/evidence/sync-coverage-evidence.json`, keyed by
row id, and are never copied into a row — one evidence text has one home, and `SyncCoverageGateTests` checks
the declared anchor count against the entries that file holds for the row.

## Guard

`SyncCoverageGateTests` holds this page and its evidence file. It fails when a `NetMsg`, `WireCommandKind`,
`WireEventKind` or `AdaptiveStreamId` member has no index entry, when an entry points at an unknown row or
at a row that does not mention the member, when a row's verdict leaves the vocabulary, when a row declares
no anchor or its anchor cell is not a count, when a row id is duplicated, when the matrix drops below its row
floor or the evidence file below its entry floor, when a row repeats evidence text (`path 'quote'` — the
quote belongs in the evidence file only), when a row's declared anchor count disagrees with the entries that
file holds for its row id, when an evidence entry's quote is no longer present in the file it names, when the
evidence file's declared `count` disagrees with the entries it carries, when the verdict summary disagrees
with the rows, or when a gap row names no existing `docs/backlog/todo/*.md` ticket. Each failure mode has a
negative-contract self-test.

**What the guard proves, and what it does not.** It proves that the row, the evidence file and the sources
agree. It does NOT prove that a quote is *relevant* to the row that owns it: the count is a declaration
check, not a completeness proof, so an edit that deletes entries and lowers the count in the same change is
not caught mechanically. The floors bound how much evidence can vanish silently; a review of the evidence
diff covers the rest.

Known limitation, re-measured on the rewritten page: of the 1,049 entries in
106 carry a quote whose text occurs more than once in the file it names, so such a quote cannot pin its own
position on its own and its row relies on its longer sibling quotes. All other evidence is uniquely
anchored.
