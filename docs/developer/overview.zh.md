# 总览

[English](overview.md) | 中文

CUO 为一个本来没有多人的游戏加上多人。它的做法是自己拥有玩法事实:一个带类型的确定性内核保存世界的
权威状态,而 Unity 场景、网络缓存与存档文件都是由它构建出来的投影。

模组分成稳定的运行时与可替换的适配器,这样游戏更新破坏的是适配器,而不是协议、会话逻辑与模组 API。

## 模组的形状

- **主机**运行权威内核;**客机**发送自己的操作,并应用主机提交的结果。
- **运行时(Runtime)** 拥有协议、会话状态机、模组加载、序列化与日志。
- **适配器(Game Adapter)** 是唯一了解游戏私有类型的层,并吸收游戏更新带来的变动。
- **GameState 内核**拥有带类型的状态:物品、玩家、实体、世界、流体,以及改变它们的规则。
- **投影(projection)** 把已提交的状态转成 Unity 物体、远端克隆体、网络批次与存档。

## 一条指令的旅程

玩家做了某件事。客机把它变成一条指令发送出去。在主机上,内核判断是否接受它,产生一个已提交批次,
并广播该批次;随后每一侧归约它并投影出结果。在提交之前,任何东西都不是权威的。

## 为什么必须确定性

每一侧都必须从相同输入得到相同的世界状态,所以内核从不直接读取时钟、随机数或 Unity 对象;
它们作为显式输入传入。这样才可能回放,而回放正是测试框架在不启动游戏的情况下验证行为的方式。
