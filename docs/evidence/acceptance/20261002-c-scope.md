## Findings and observations

- **The late-joiner delivery path that works on this machine** is the member re-entry against a host
  that stays in the world: a re-handshake of a member whose host is `InWorld` receives a direct
  `WorldJoin`, and the member's re-entry edge makes the host send the world-entry snapshot group
  (with the block-damage snapshot read at send time). The `leave → continue` path used to need the
  `lastOpenedWorldId` pointer moved to this session's world first (a new run did not move it; the Worlds
  page's `worlds.select.<worldId>` was the native way); **from 2026-10-02 the run's first committed cut
  moves it** (`WorldSaveService.OnCutReported`), so that workaround is retired for the normal case.
- **The batch-`20261002-b` write-echo question is answered**: the presentation's own write IS reported
  back. `WorldEventSync.OnBlockSet`'s early return does not cover this path end to end.
- The recorded SteamIds are replaced by placeholders in these records.
- Ticket `sandbox-client-null-reference-bursts` is opened for the sandbox exception bursts.
