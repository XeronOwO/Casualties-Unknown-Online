# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: the ticket's status carried the s2 reading before the edit; the applier `WorldBuildingEntitySync.ApplyRemoteBuildingEntityHealth` was read first.
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — evidence: the game's damage path reports `ReportBuildingEntityHealth`; the restore applier writes `entity.health` and marks a remote death, the live relay's own semantic.
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: the mine's own explosion damaged 7 buildings on the host (armed 7 health rows); the member side was not in this batch and is named as the limit.
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): no player gesture changed; the entry is the console verb's own line — evidence: no gesture; the entry is the mine's own explosion (`trap-trigger`) plus `/save`, `leave-world`, `continue-run`.
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: both null branches in `WorldBuildingEntitySync` and the live arm/take lines in the log.
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: the health applier (destroyed fact satisfied) and the opened applier (gone lockable IS opened) both fixed; the damage relay's null branch stays a warning because its return is ignored — named.
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: no table; two null branches plus a three-fact source gate (`RestoredBuildingHealthGateTests`).
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: the live batch `20261108-s3` on `0.1.0+7b77a39a`: cut 10 rows, armed 7 health rows, refused 2 (down from 6 of the same shape).
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: the user's instruction to push one ticket all the way through.
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: no class size changed materially; the file is not on the watchlist's at-limit list.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build 0/0; format exit 0; gates `passed - 0 failed, 831 passed`; suite `passed - 0 failed, 6622 passed`.


- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
