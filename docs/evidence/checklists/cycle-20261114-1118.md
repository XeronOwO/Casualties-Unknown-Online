# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.
- [x] Design comprehension — the ticket's root cause is corrected to our own example mod's recipe — evidence: the status line
- [x] Native parity — the vanilla game opens the crafting screen; the mod layer is the difference — evidence: the ticket's corrected section
- [x] Native parity probe — the deployed build opened the panel (`panelActive: true`) with one placeholder line and no NullReferenceException — evidence: the acceptance read of 2026-11-14
- [x] Entry mapping — the craft key → OpenCraftScreen → RefreshRecipeList → Recipe.resultSprite chain is written on the ticket — evidence: the ticket's chain block
- [x] Mechanism inventory — one getter feeds every list refresh; the patch is owned by the Crafting capability — evidence: the catalog entry
- [x] Whole-family audit — the fix moved with the ticket into `done/` with its index and census rows — evidence: `git status` R entry
- [x] Self-check table — the README row moved to Done and the census path follows — evidence: the diff
- [x] Verification design — gates 834/834 after the move; the reading carries its numbers — evidence: the gate capture
- [x] Plan approved by the user — the user ordered the fix — evidence: the request
- [x] Structure review done — no source change in this cycle — evidence: the diff is docs only
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: gates 834/834

- [ ] Release-cycle deployment/acceptance: the fix was deployed and read in the previous cycle

- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
