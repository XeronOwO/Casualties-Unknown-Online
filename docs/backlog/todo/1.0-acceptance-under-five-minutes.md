## Design

The rows exercise the world lifecycle described in
`docs/design/game/worldgen-and-layers.md`: a new world is generated once,
the member joins its running baseline, and leaving must go through the run's
own leave edge rather than a bare scene load. The acceptance fixture follows
that edge so its readings describe the product, not a shortcut.

## Experiments already measured

- `role-clearing` now reuses the running world instead of restarting:
  70.1 s → 21.7 s. It first returns the host overlay to Home, because the
  preceding `worlds-page` row leaves it on Worlds and `home.leave` is not
  offered there.
- `remote-removal` now leaves through the product's `TryDeferMenuReturn`
  edge, waits for the host clone to disappear, and does not force a rejoin:
  30.0 s → 6.5 s. It runs after `role-clearing`, which is the last row that
  needs the pair.
- The member's session clear now sends the same leave intent before the
  session-leave click. Without that sequence the member kept
  `role=Guest, active=true, inWorld=true, page=Home`, and the next
  `character-choice` could not join.
- **2026-11-16 — unchipped initial world (reverted).** Starting the setup
  world with the host's `unchipped` preset made `late-layer-switches` an
  InRun row and removed 45.4 s of restart: the focused three rows passed
  (setup 25.9 s; late-layer 0.8 s; pod 15.4 s; last-layer 27.4 s), and a full
  suite measured **328.8 s**. The run is not usable as the suite base:
  `radiation-line` went red because the native line activation is explicitly
  disabled in an unchipped world (`WorldGeneration.cs:986` includes
  `!WorldGeneration.unchipped`). The experiment was reverted; the green
  baseline remains 358.8 s. Option B must therefore start the unchipped world
  **after** `radiation-line`, not replace the initial normal world.
- The pod gate reads the host's replicated entity position, not the member's
  local body transform. A test-only `entity-place` fixture made both pod rows
  pass in the unchipped world; it was part of the reverted experiment, not a
  product change.

## Options

1. **A — make leave update the run coordinator** (recommended): after the
   native menu return, the run state must be out-of-world even when the old
   world object is still alive. Then `role-clearing` can reuse the pair and
   save its 45.8 s restart; `remote-removal` can rejoin without the ghost.
2. **B — split character-choice and merge its world with late-layer**: run the
   choice/peer half first without the ending, run `late-layer`/`pod`/`last`
   in that unchipped world, then run the ending + outside picker at the end.
   Saves the 44.3 s late-layer generation.
3. **C — start setup from a generated world fixture**: restore instead of
   generate, reducing the 22.8 s setup. It changes the fixture's isolation and
   needs a separate decision.

A and B are implemented. C remains, only if A/B still miss the target. Never
park a red row.
