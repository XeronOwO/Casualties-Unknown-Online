# The heal leaves the limb's skin where the damage put it

- Status: Todo
- Priority: High
- Created: 2026-11-28

## Why

In a batch, the game answers a heal (`applied: true`) and the limb's skin stays where the last damage
put it. `full-62`'s `drop-mid-transfer` row read the host's abdomen at `{"i":2,"name":"Abdomen",
"skin":63.926,...}` after the host's `/heal @a`, and the same batch's give/craft rows read
`no-free-slot` while the member's bag was empty — a slot whose limb is missing cannot take an item, and
the heal that should bring the limb back is the one that is not landing.

## What the readings say

- `full-62` (66 rows, deployed `0.1.0+4c3ad0912`): `drop-mid-transfer` FAIL 19.2 s, host note
  `the body still reads what sample-mod left after the host's '/heal @a': {"i":2,"name":"Abdomen",
  "skin":63.926,...}`.
- `full-62`: `give-container-sound`, `crafting-outcome`, `two-member-continue` and
  `remote-backpack-refresh` all read `{"ok":false,"error":"no-free-slot","detail":"every body slot is
  occupied or unusable"}` in the same batch.
- The world guarantee's slot probe (`SessionDriver.SlotNoteAsync`, 1656-1689) heals both bodies when a
  body has no carry slot, and records the note; the rows still met the unusable slots afterwards.

## The code the write passes through

- `HealResetState.ApplyTo` (`src/CasualtiesUnknownOnline.GameAdapter/Character/HealResetState.cs:233-298`)
  sets `limb.SkinHealth = HealResetState.LimbSkinHealth` (100).
- `CharacterDataCapture.CaptureLimbs` (`CharacterDataCapture.cs:117-135`) maps each live limb with
  `mapper.Map<CharacterLimbMsg>(body.limbs[i])` and stamps `Index = i`.
- `CharacterDataSync.ApplyHealState` (`CharacterDataSync.cs:503-517`) maps each row back with
  `_mapper.Map(limbData, body.limbs[limbData.Index])`.
- `Limb` is a `MonoBehaviour` with a plain `public float skinHealth` field (`reversing/release-1.0.2/
  Assembly-CSharp/Limb.cs:8`), so the write target is a live reference — the miss is either in the
  Mapster configuration (`CharacterDataMapper` 46-58 maps the prosthetic explicitly and leaves the rest
  to convention) or in a later writer that re-stamps the limb from a stale snapshot.

## Options

1. Probe the write where it lands: log, after `ApplyHealState`, the limb index and its `skinHealth` for
   the abdomen — the same shape as the hand-over probes. Then fix whichever side is short.
2. Map `SkinHealth`, `BleedAmount`, `Pain` and `MuscleHealth` explicitly in `CharacterDataMapper` and
   prove the mapping by a unit test on a live `Limb` (no batch needed).
3. Accept the batch shape as a row-side precondition and keep the rows waiting on the heal — rejected:
   it hides a product bug the rows exist to catch.

Recommended: 2, then 1 only if the explicit mapping still misses.

## Done when

`drop-mid-transfer` reads the host's abdomen at 100 after `/heal @a` in a batch, and the four
`no-free-slot` rows can put an item into the member's bag in the same batch.

## Design

The heal is a custody-free state write: the deciding side is the client that owns the body, and the
wire carries the limb record (`CharacterLimbMsg`). `docs/design/model/health-and-limbs.md` states the
rule this row reads; `docs/design/cross-cutting/saves-and-recovery.md` carries the restore-side use of
the same row.
