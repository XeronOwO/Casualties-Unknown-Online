## What "C# acceptance" means here

- A row is a class under `tests/CasualtiesUnknownOnline.AcceptanceSuite/Cases/` registered in `CaseRegistry.All`; it
  drives the game through the in-process channel and asserts on readings.
- A recipe is the in-process primitive a case calls — C# deployed into the acceptance assembly, never a script the case
  shells out to. Recipes stay as primitives; the acceptance code is the case.

## Orphan-recipe cleanup (2026-11-19)

The set was proved with one reference pass, not a per-name repository walk (which timed out): every case source was
searched for the quoted recipe name; every other recipe's text was searched for the name; finally a single tokenised
pass over `docs/`, the acceptance scripts, the driver sources and the local notes answered whether a name is still
mentioned anywhere. Counts: 106 case-referenced, 150 mentioned elsewhere in the repository (kept, they are staged by
other fixtures or named in the records), **23 proved orphans**, deleted one file at a time after each path was checked
to be a single file inside `tools/acceptance/recipes/` (never recursively):

`receive-watch2-start, heart-rate-set, sound-play-probe, input-probe, audio-watch-b-read, pointer-shake,
body-sleep-force, item-motion-sample, blood-watch-start, receive-watch3-start, heart-beat-probe, shrapnel-observe5,
play-watch-start, report-watch-start, receive-watch-start, audio-watch-b-start, publish-watch-start,
generation-audio-probe, anim-watch-start, body-swap, harmony-probe, radline-timer-read, pinyin-probe`.

The layer went 328 → 305 files. The acceptance suite builds with 0 warnings and 0 errors, and the gate project reads
836/836 on the same tree. Limitation written down rather than hidden: the scan matches literal names, so a recipe
invoked through a computed string would look orphaned; `grep` over the recipe loader shows every call site passes a
string literal, and this row would have caught a deleted name at the suite build if one were referenced.

### Second pass (2026-11-19, after the premature close)

The 23-orphan pass only removed names mentioned **nowhere**; 164 of the 305 survivors were still referenced by neither a
case nor another recipe. This pass is the one the ticket's condition asks for:

- 141 recipes remain in `tools/acceptance/recipes/` and every one of them is referenced by a case or by another recipe.
  The re-scan now matches names as whole tokens (a boundary, not a substring) and reports 0 unreferenced.
- 104 names with no live reference were deleted one file at a time (`Remove-Item` on a verified single-file path, never a
  recursive delete): they were one-off probes from investigations whose readings already live in the tickets.
- 60 names still cited by a live procedure page are not stray code — they are the manual instruments a diagnosed row
  needs (a state read, a forced body state, a lease probe). They moved to `tools/acceptance/probes/`, so the recipe
  layer holds only what the suite uses; `drive-in-process.ps1` looks a name up in `recipes/` and then in `probes/`, and
  each of the 60 keeps working under the same name.

The two layers are now distinct vocabulary, not debris: `recipes/` = what a case runs, `probes/` = what a person runs
while diagnosing one.
