# Delivery checklist

Fill every box, then run `tools/check-delivery.ps1`. Each box needs the literal ` — evidence: ` followed by the evidence.

- [ ] Design comprehension — a parked ticket must keep the folder label the backlog gate requires, and the goal gate must not read that label as leftover work
- [ ] Native parity — no native chain is mirrored or replaced; the change is the goal gate's status scan
- [ ] Native parity probe — no probe: the gate's own two runs are the check, one with a residual word and one without
- [ ] Entry mapping — one entry: the residual scan in the ticket loop strips the folder label before judging
- [ ] Mechanism inventory — one residual pattern and one parked pattern, both unchanged in meaning
- [ ] Whole-family audit — the label set matches the backlog gate's folder-to-label map exactly (todo/review/in progress/done/resolved/future/watchlist)
- [ ] Self-check table — the gate must pass the parked ticket and refuse a residual claim
- [ ] Verification design — backlog gate, goal gate, build, units, format
- [ ] Plan approved by the user — the night goal authorises self-chosen ticket work without asking
- [ ] Structure review done — the strip lives beside the pattern it serves, with the reason in a comment and the header
- [ ] Build + dotnet format + dotnet test normative gates pass
- [ ] Release-cycle deployment/acceptance
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
