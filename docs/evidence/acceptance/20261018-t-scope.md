## Method

The prelude started the host and the member, created and joined one lobby and entered one run
(`prelude.log`: `inWorld: host=True member=True`). Rows were driven one step at a time through the
in-process driver: pages through `goto-page`, fields through `set-text`, buttons and swatches through
`click`, the window through `open-window`/`window.close`, and the console through the driver's `console`
and recipe actions. A user-authorized **one-time foreground switch** of the host client (`foreground.ps1`,
`before=68658 after=1117794`) was required for the key rows: the committed `window-key` channel posts
messages to the client's own window, and the game does not read them while its window is not the
foreground — the same failure shape batch `20261011-e` recorded. The switch changed the focus only; no
pointer or keyboard event was injected from the OS. The user also asked for a heal before the long work. The run sent `/heal @s` (host) and `/heal @a`/`@p`
(member) at 11:20. The host was already **unconscious** by then: `/heal @a` and `/heal @p` were refused by
the host-side handler (`[Heal] refused: <host> is not conscious/alive and cannot heal.`), and `/heal @s` was
dropped silently by the self-target guard (`healer == target`) — no `[Heal]` line at all — while the command
answered `Sent heal request to N player(s)` for all three. The heal was both too late and the wrong wiring:
the run used CUO's `/heal` while it was still wired to the remote-medical item service (the cross-player,
conscious-healer, carried-item rules), not the command the user wants. **The user corrected the design after
the run (2026-10-18): `/heal` is a CUO-console CHEAT command that immediately resets the selected player's
state — full reset (KrokMP's body fields + the native limb fields + CUO's severed limbs and hollow),
cheat-family permission, dead targets revived** (`docs/backlog/done/heal-cheat-command-state-reset.md`). The
CUO console is an independent extension of the game's console; the native `heal` existing does not remove
the need for it, and the item-based treatment stays the remote-medical UI's action. The workflow now carries
the three-surface prelude rule (game `heal`, CUO `/heal` cheat reset, item path; heal early and read the
vitals back). The rows this batch judged do not depend on the host's health; the medical-panel frame (row 8)
is read as the readout the launcher covers, not as a healthy-state claim.

The window capture had to be DPI-fixed for the edge-anchored surfaces: the standard window capture returned
1038x614 of a 1280x720 client, cropping the canvas's right and the bottom (the launcher and the docked quick
panel fell outside it), so the run's capture helper calls `SetProcessDpiAwareness(2)` before
`GetWindowRect`/`PrintWindow` (`capture-dpi.ps1`). The `cuo-ui-dump` recipe's answer exceeded the
evaluator's value cap on the Admin page (`truncated`), so the run used a compact ad-hoc probe of the same
window tree (`snippets/ui-probe.cs`); the committed recipe was not changed.

Setup substitutions, declared before the run and named in the records:

- **No OS pointer or keyboard input.** Keys were messages on the client's own window; clicks were control
  intents. The hover half of the launcher row is a residual for the user.
- **The medical panel** was opened through the game's own `PlayerCamera.WoundViewButton()`.
- **The drag row** was driven through the production `OnlineUiWindowDragHandler.OnDrag` with a synthetic
  pointer delta; the pointer-down that starts a drag is OS mouse input, which the run does not take.

  window's own per-frame fit did the rest, and the scaler was restored afterwards.
- **The quick panel and the in-world player menu** were opened through their production entry points
  (`ToggleQuickPanel`, `Open`) because their gestures are a configurable hotkey and a right-click. The quick
  panel was also moved to the screen centre once to read its model while the capture still cropped the
  docked corner; the restored dock was then captured at full window size.
- **The console's opener** was also driven through `OpenCommandConsole` once (after the key opener's state
  was already proven) to re-read the closed-notification strip, because the game's own console had left its

## Lessons this run folds

- A window capture on a DPI-scaled display crops the window unless the capturing process sets its DPI
  awareness; edge-anchored surfaces (the launcher, a docked panel) are outside the crop. The rule is in
  `docs/acceptance/workflow.md` §5; this batch's DPI-aware helper is the reference implementation.
- The committed `window-key` channel needs the client window in the foreground; `posted=true` with
  `heldAtEnd=false` is the tell. `docs/acceptance/workflow.md` §5 carries the check and the one-time
  user-authorized switch.
- The game's own console leaves its input selected after it closes; a guard that asks "is the selected
  object a text field" latches. The Enter ticket carries the fix; the lesson is in its record.
- A heal is a SETUP step with three independent surfaces: the game's own `heal` console command (item-free,
  local body); CUO's `/heal` cheat command (the immediate full reset of a selected player, cheat-family
  permission — `docs/backlog/done/heal-cheat-command-state-reset.md`, not yet landed); and the
  remote-medical UI's item-based treatment. The run used the old item-based wiring on the CUO command; the
  user corrected the design, not the command's existence. Restore early — an unconscious healer is refused —
  and read the vitals back. `docs/acceptance/workflow.md` §5 carries the rule.
- The language split (host Chinese, guest English; a host-only English pass returns to Chinese) is in the
  local `docs/acceptance/AGENTS.local.md`, not in git; the next batch applies it.
