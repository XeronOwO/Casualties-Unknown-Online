- Batch: `20261001-t` — offline: no game client is started. Every row is decided by this run's own
  build, suites, gates and tools, or by a comparison/measurement this run performs against a
  revision held in the repository's own history. Rows are classed `machine`; a row decided by
  inspection or by a re-derived comparison says so in its record.
- Tickets in scope (7): `backlog-index-summary-duplication`, `composition-root-feature-modules`,
  `di-cycle-guard`, `evidence-matrix-fat-rows-split`, `snapshot-size-reduction`,
  `source-shape-gate-modifier-blindness`, `session-environment-gate`.
- Why these: batch `20260927-b` classified every one of them `offline` and left it in `review/` with
  the evidence kind it still needs named in that batch's scope. One of those kinds has since landed
  (the `new` sample of the source-shape gate); the rest are this run's work: a re-derived
  comparison (index facts vs their tickets; matrix rows vs the pre-change revision; registrations
  and lifetimes vs the pre-split revision), a measurement (the checkpoint sizes; the composition
  build bound) and the tool's live read-only half. `systemic-save-backup-management` — the sixth
  ticket that scope named — is deliberately out of this batch: its remaining delivery rides
  `world-and-backup-management-surface`, a session ticket, and the umbrella moves with its last
  stage.
- Out of batch, deliberately: every session-family ticket. The medical, UI and sync families need a
  running client (a captured frame, a live log line, an in-process probe or a two-client
  observation); their batches are named in the closing handoff, not judged here. A row this run
  cannot ground from repository evidence is `unproven` with the gap named, and its ticket stays in
  `review/`.

## The evidence channel (declared before the run)

- **machine**: this run's `dotnet build`, the two suites (the main suite and the normative gate
  project), per-test outcomes and durations from the run's own logger output, `dotnet format`, and
  the artifact identity check (`tools/verify-deploy.ps1`). The deploy is verified but no client is
  started.
- **re-derived comparison**: the run reconstructs the pre-change state from the repository's own
  history (`git show <revision>:<path>`) and compares it against the tree — the rewrite's index
  facts against the tickets, the evidence matrix's ids/order/verdicts/gap tickets against its
  pre-change revision, and the composition root's registrations against the pre-split file.
- **run-local probe**: the checkpoint-size measurement and the production-composition build bound
  are taken by a temporary probe file that is deleted before the final ladder; its output is written
  into the batch directory under `acceptance-artifacts-dir` and cited as this run's artifact. No
  product or test file is changed by it in the delivered tree.
- **machine read-only**: `tools/acceptance/session-environment.ps1 -Mode status` against the real
  install (classification only; no swap is performed for this batch).

## Limits (declared before the run)

- **No runtime behaviour is observed.** A row decided by a repository test, gate, tool output,
  comparison or measurement says so in its record's `Limits`.
- **Historical states are re-derived from this repository's own history**, never from memory: the
  revision each comparison reads is named in the record. A claim whose pre-change state cannot be
  reconstructed is `unproven`, not accepted.
- **A run-local probe is not a committed test.** The probe is deleted before the final ladder; the
  delivered tree is the unmodified one, and its output file is the artifact a record cites.
- **The gate stays the tree.** Every row is judged against this working tree at the commit the
  record names; an earlier cycle's numbers are never this batch's evidence.
