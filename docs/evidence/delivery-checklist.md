# Delivery checklist

Fill every box, then run `tools/check-delivery.ps1`. Each box needs the literal ` — evidence: ` followed by the evidence.

- [ ] Design comprehension — the row's claim is that an item arriving in the owner's backpack reaches a member's already-open window
- [ ] Native parity — no native chain is mirrored or replaced; the seam refuses one production render call in an acceptance-only assembly
- [ ] Native parity probe — no probe: the row reads the native window's own slot buttons through `containerUnloadButtons`
- [ ] Entry mapping — one entry: `AcceptancePlugin.Awake` installs the seam and the trace beside the recorders
- [ ] Mechanism inventory — five case-scoped red seams, each armed only by `CUO_ACCEPTANCE_RED`
- [ ] Whole-family audit — every seam returns the untouched path unless its case is named; eight C3 seams were measured, and the narrow one failed at the row's precondition because one call builds the container and draws the arrival
- [ ] Self-check table — the red must fail and the same case must pass with the variable unset on the same artifact
- [ ] Verification design — build, units, gates, format, deploy `-Acceptance`, red run, green rerun
- [ ] Plan approved by the user — the night goal authorises self-chosen ticket work without asking
- [ ] Structure review done — the patches are stateless, resolve their targets by name, and the trace writes into the client's log folder so the deployed inventory stays comparable
- [ ] Build + dotnet format + dotnet test normative gates pass
- [ ] Release-cycle deployment/acceptance
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
