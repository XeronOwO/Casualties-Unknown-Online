# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: `review/native-console-is-unpoliced.md` §The push-back (open) names the directed reply, the local-body write and the batch reading; written before the first src edit.
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — `docs/development/native-parity.md` — evidence: the host's record (`LimbStateEventHandler` + `CharacterDataStore`) answers a refused report with the same `LimbStateEvent` frame shape the game's own limbs produce; the member writes it onto its own `Body.limbs` with the field set `CloneLimbRenderer` already uses for clones.
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: batch `20261108-t2` ran the native heal on Steam2 (local 100/100, host refused); the post-fix batch reads the correction on the same client.
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): no player gesture changed; the entry is the refusal branch of the limb report — evidence: `LimbStateEventHandler.Handle`'s refused branch calls `PushBackTheRecord`; no new gesture.
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: `LimbStateEventHandler.cs` (refusal + push-back), `ISessionControl.SendTo` (directed send), `CharacterDataSync.OnLimbStateEventReceived`/`ApplyHostLimbCorrection` (local-body write), `CloneLimbRenderer.cs:118-137` (the field mapping mirrored).
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: the correction writes every limb field the report carries in one loop (not only skin); the other native verbs (`kill`, `spawn`, item/block) never take this path — their facts are host-originated and the ticket names them as the residual.
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: the ticket's §The reading + §The push-back name the frame, the directed send and the local write; the live batch reads the guest's limbs after the reply.
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: the host log's `sent the host's record back to {Peer}` and the guest's `applied the host's record to the local body`, plus the limb read after the exchange.
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: the user's rule (2026-11-08): the host must correct the guest after the periodic report, not only keep its own record.
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: `LimbStateEventHandler` +40 lines, `CharacterDataSync` +52, `SessionService` +2, `ISessionControl` +5; no state bools added; no dead code.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build 0 warnings/0 errors; `dotnet format` exit 0; gates `831/0`; suite `6628/0`.


- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
