# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: `docs/design/surfaces/online-window.md` carries the box and the ceiling rules; the ticket's delete section now also carries the ceiling editor
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — `docs/development/native-parity.md` — evidence: n/a, no native counterpart (the game has no world library); the frame reuses the game's own window sprite through `OnlineUiControlFactory.MakeFrame`
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: n/a for the same reason
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): the entry is every control of the CUO window — evidence: the ceiling field is the page's own control (`worlds.retention.number`), the box is chrome inside the page's scroll content
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: `CreatePageBox` (`OnlineUiSurfaceParts`), `MakeFrame`'s border/fill pair (read), `IBackupRetentionWriter` → `SaveConfigRetentionWriter` → the config entry (read)
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: MECHANISM census: the box is one decoration for every page (not a per-page patch); the ceiling has one writer and one reader
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: this cycle's rows: box (frame + fill under the rows), ceiling (number field → config entry → monitor)
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: the live page reading (the box's border visible under the rows, the field showing the ceiling and writing the config)
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: the user's "I said finish it in one go, understand?" (2026-11-09, translated) after the previous report named the frame and the ceiling editor
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: `OnlineUiWindowView` was 611 and is back at 600 by moving the box into `OnlineUiSurfaceParts.CreatePageBox`; no state bools added
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build succeeded; format exit 0; gates 831/0; suite 6637/0


- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
