# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.
- [ ] Design comprehension — the heal reset's write path is the ticket's subject, not this cycle
- [ ] Native parity — the probe reads the game's own log and limb state
- [ ] Native parity probe — the reset applies while the limb reads hurt
- [ ] Entry mapping — one ticket section added
- [ ] Mechanism inventory — the failure rate and both readings recorded
- [ ] Whole-family audit — the same file keeps its earlier readings
- [ ] Self-check table — documentation only
- [ ] Verification design — the next cycle's probe is named
- [ ] Plan approved by the user — the goal's main line
- [ ] Structure review done — the section lives on the ticket it judges
- [ ] Build + dotnet format + dotnet test normative gates pass

- [ ] Release-cycle deployment/acceptance: nothing deployed this cycle

- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
