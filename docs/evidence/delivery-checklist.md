# Delivery checklist

Fill every box, then run `tools/check-delivery.ps1`. Each box needs the literal ` — evidence: ` followed by the evidence.

- [ ] Design comprehension — the runbook's structural half stops at contract verdicts, so the update's behaviour needs the batch's readings; rule 14 fixes the baseline
- [ ] Native parity — no native chain is mirrored; the comparer reads our own suite report and the game is not touched
- [ ] Native parity probe — no substitute exists; the report's own fields are the readings, and a Markdown report is never parsed
- [ ] Entry mapping — one entry: the `replay` verb added to the host's switch and its help
- [ ] Mechanism inventory — the runbook's chain is contract diff → offline replay → live batch replay → verdict; this change adds the third link and the verdict consumes its exit code
- [ ] Whole-family audit — the five ways a batch can move are covered: lost row, verdict, case wall, suite wall, errors; warnings were measured and excluded because a green pair moved ten
- [ ] Self-check table — every promised refusal has a row in `ReplayToolTests` (lost row, verdict, wall, errors, different suites, unstamped report, not-a-report), 7 of 7 green
- [ ] Verification design — focused tests first, then real reports both directions and the refusal, then the full pipeline
- [ ] Plan approved by the user — the night-mode goal authorises self-chosen ticket work without asking
- [ ] Structure review done — one comparer in the acceptance host, no state, no product dependency; the tolerance floors are CLI options with the recorded defaults
- [ ] Build + dotnet format + dotnet test normative gates pass
- [ ] Release-cycle deployment/acceptance
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
