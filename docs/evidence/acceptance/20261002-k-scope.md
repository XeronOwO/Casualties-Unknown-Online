The batch serves the world/item/entity-identity core — tickets whose remaining rows share one
world, one pair of clients and one third client:

|---|---|---|
| `guest-block-mutation-re-report` | High | 1–6, 8–10 |
| `runtime-entity-spawn-backfill` | Medium-High | 1–12 |
| `enemy-snapshot-binding-recovery` | Medium | 1–8 |

deliberately out of scope; they are named in §4 with the batch that should serve them.

## 2. Setups the session will run

One host on the physical machine, one guest in the Sandboxie guest box, one alternate client in
the second box; all enter the same world through the Online UI's own controls, driven in-process.

- **A — world entry and steady state.** Create lobby, join with both peers, start the run, close
  the Online UI before any world frame. Serves the idle halves of every ticket (empty enemy
  table no-op; entry-group ordering).
- **B — block mutations.** A marked cell: guest mines, guest places; the host and the third
  client read the same cell. Serves `guest-block-mutation-re-report` rows 5, 6, 9 and the
  first-writer-wins row of `world-layer-generation-identity` (row 3).
- **C — runtime entity spawns.** Spawn animals through the committed probe path; check late
  joiner, in-world reconnect, same-cell siblings, destruction before re-report, layer
  regeneration, accepted-animal table and the shared enemy id set. Serves
  `runtime-entity-spawn-backfill` rows 3–10, `enemy-snapshot-binding-recovery` rows 1–6 and 8,
  and `generation-identity-remaining-families` row 3.
- **D — item creation then operation.** Guest creates and immediately operates; two senders on
  one item; reconnect/late-join semantics. Serves `item-creation-registration-first` rows 1, 3,
  4, 5 and 7.
- **E — layer change.** `skiplayer` (or a natural descent): the third client's view after the
  change, the new layer's first writes. Serves `world-layer-generation-identity` row 5,
  `generation-identity-remaining-families` rows 5 and 8.
- **F — fresh world entry.** Leave the world and re-enter it so the one-shot `[WorldFingerprint]`
  pair is emitted again after a mutation pass. Serves `world-determinism-world-fingerprint`
  row 3.

Rows whose setup is not in this list are judged from the same session's logs and probes when
they can be, and recorded `unproven` with the missing setup named when they cannot — never
guessed.

## 3. Capability boundary

Established by earlier batches (see `docs/acceptance/lessons.md` and the earlier scope pages):

- **No packet-loss injection.** The machine can stop a whole transport pump, but the peer's own
  watchdog ends the session first; "the send succeeded and the receiver never got it" is not
  reproducible here (batch `20261001-x` scope page). Rows whose setup is a swallowed report
  are recorded `unproven` with that reason.
- **No IP-direct same-name roster.** Never staged; rows needing it stay `unproven`
  (batch `20261001-o`).
- **No window-focus control.** Foreground/background rows stay `unproven`
  (batch `20261001-l` scope page).
- **The shipped zoom cannot resolve item sprites**, so crop-based visual rows calibrate on an
  in-frame landmark first or stay `unproven` (batch `20261002-e`).
- **One two-client session at a time**; runs are serialised.

## 5. Exit criteria

- One record per ticket: `docs/evidence/acceptance/<slug>-20261002-k.md`, carrying the batch,
  commit, artifact identity, the per-row classification, one verdict and one evidence pointer
  per row, and the limits.
- Transition per workflow §8: all rows `pass` (or `residual` only) → `docs/backlog/done/`;
  a `fail` or `unproven` row → `docs/backlog/todo/` with `- Status: Todo — Rejected (…)` and
  the row named; a `blocked` row keeps the ticket in `review/`.
- Index rows move in the same change; the gate project runs; the run folds its lessons back
  into `docs/acceptance/lessons.md` before it closes (workflow §10).
