# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle.

- [ ] Design comprehension — the chip body was read against the reading
- [ ] Native parity — the nested bracket logs the entry state and facts
- [ ] Native parity probe — identical entry, different exit
- [ ] Entry mapping — the facts are read at the bracket, not at save time
- [ ] Mechanism inventory — the body cannot produce two different results from one state
- [ ] Whole-family audit — the contradiction is recorded, not smoothed
- [ ] Self-check table — documentation only this cycle
- [ ] Verification design — the next probe sits inside the method
- [ ] Plan approved by the user — root cause first
- [ ] Structure review done — the finding contradicts the code and says so
- [ ] Build + dotnet format + dotnet test normative gates pass

- [ ] Release-cycle deployment/acceptance: no deploy in this cycle

- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
