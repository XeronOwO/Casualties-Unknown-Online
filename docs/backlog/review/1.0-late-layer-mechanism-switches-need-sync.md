# Late-layer mechanism switches need one answer on both clients

- Status: Review — filed from the friend session on the reference mod (Together, formerly KrokMP); our own
  late-layer rows are not yet driven.
- Priority: High

## Design

Read: `docs/design/game/worldgen-and-layers.md` (the last layer's own rules and the descent) and
`docs/design/mechanics/world-interaction.md` (what an authoritative fact is on the wire).

## What the user measured (2026-11-14, translated)

"After playing, the Together mod's last layer has a lot of bugs — for example, a guest without a chip
cannot attack or use items after the cutscene — and many gameplay-mechanism switches need synchronising.
Please watch for this."

## Why it matters here

The last layer is where the game changes its own rules: the descent cutscene, the chip state, the
attack/use gates and the layer-end switches all flip at once. A client that keeps the previous layer's
flags keeps the previous layer's abilities — the reference mod's symptom is exactly that shape (the guest
is still gated after the cutscene).

Our design rule already says a client's copy of an authoritative fact is synced, never clamped. The
question this ticket asks is which mechanism switches are authoritative facts on the wire today and which
are still read locally.

## What to read before the first probe

1. The game's own gating for attack and item use on the last layer — `PlayerCamera`/`Body` fields the
   cutscene writes, and the panel/console paths that read them.
2. Our capture: which of those fields ride `WirePlayerStreamState`/`PlayerVitals` and which do not.
3. The descent edge: `SendLayerDescent` and what the member does with its own flags after accepting it.

## Acceptance rows

1. Both clients descend to the last layer; after the cutscene BOTH can attack and use an item (read from
   each client's own action, not from the host's screen).
2. A mechanism switch that the game flips at the layer boundary reads the same value on both clients
   within one second of the descent (read from each client's own state).
3. A member that joins after the descent sees the same switches as the clients that descended together.

## What must not change

- The wire shapes the session already carries for the player stream; this ticket adds a fact only when the
  game has no sync path for it.
- The layer descent's own edge and its gate: the member still generates its own layer from the host's
  baseline.
