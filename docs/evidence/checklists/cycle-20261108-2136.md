# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: `done/console-input-keys-violate-the-minecraft-rules.md` §Design names `docs/design/surfaces/command-overlay.md`; the fix follows the ticket's rule.
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — `docs/development/native-parity.md` — evidence: no native behaviour mirrored; this is the console's own input policy, judged against the documented contract.
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: not applicable (no native action); the batch reading drives the console keys in-process.
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): no player gesture changed; the entry is the path the ticket names — evidence: the up/down arrow and Enter branches of `CommandConsoleOverlay`; no new gesture.
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: `CommandConsoleOverlay.cs:319-327` (arrow branch), `ConsoleInputSession.DisplaySuggestions` (`_historyJump`), `PreviousHistory`/`NextHistory`.
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: the flag is set by both history keys and cleared by every text change path (typing, `SetInput`, open, close), so no sibling key path keeps the old behaviour.
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: the ticket's Fix paragraph names the flag, the property and the overlay branch that consumes it.
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: the console's own session APIs; the batch opens the console, presses up three times and reads `DisplaySuggestions.Count` between presses.
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: the user's report (2026-11-08) and the "continue" instruction.
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: `ConsoleInputSession` 597 lines after trimming the comments (the aggregate gate's 600-line cap); no new type; the flag is a per-input state, not a world bool.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build 0 warnings/0 errors; `dotnet format` exit 0; gates `831/0`; suite `6628/0`.


- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
