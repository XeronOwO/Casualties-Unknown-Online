## 2. Setups the session will run

- **A — entry generation, host present.** Three clients enter one run; each side's `[GenStream] done`
  count and `[LayerMod]` line are read. Serves the regression row (host present for the whole
  generation) and the host-path row.
- **B — mutation pass and on-demand fingerprint.** A marker cell is written with the absolute-grid
  recipe, the three clients' cell reads are compared for convergence, then the new `world-fingerprint`
  recipe re-captures the product's own `[WorldFingerprint]` line on each client. Serves
  `world-determinism-world-fingerprint` row 3, with the entry lines (taken at world entry) as the
  pre-mutation pair.
- **C — member generation spanning the host's absence.** The members leave the world (staying
  connected), the host continues the run and re-invites them; while the host is settled and the members
  generate, the host leaves the world again. Serves the two decision rows.
- **D — the snapshot window.** The host continues once more so its generation snapshot lands on the
  members; the divergence-warning window is read over a full cadence. Serves the no-divergence row.

## 3. Capability boundary

- Established by earlier batches: three clients, the in-process driver, the absolute cell recipes and
  Debug log slices. New in this batch: the on-demand `world-fingerprint` recipe — it calls the product's
  own diagnostic, so the re-capture is the product's own line, not a re-implementation.
- Out of reach: a member generation spanning a host *reconnect* (not staged); the full `Random.State`
  behind the logged 16-byte windows; a wait instruction handed to a different driver that enumerates it.
- Every row here is a `machine` row: a state, a count, a log line or a converged cell read.
