evidence the run produces, the class boundary its verdicts must respect, and what it deliberately leaves
in `review/`.

  outputs. No row in this batch is `visual` or `feel`.

## 2. Why this is one batch

The twenty tickets meet on ONE evidence kind: none of their rows needs a running client. Their rows are
load-time or client-local behaviours, contract and baseline facts, or the durable outcomes of a cycle's
own verification checklist — and each of those is decided by re-running the chain and reading the tree,
which is the run this page plans. They also meet on one commit: the tree is unchanged from `3bacc6fc`, so
one build, one suite run and one deploy verify every row.

## 3. Method

The set was planned from a re-derivation over all 85 tickets in `docs/backlog/review/` (64 of them with no
acceptance record at all) — both counts as measured at plan time; the batch's own moves leave 65 tickets in
`review/`, 44 of them without a record — never from an earlier triage's headline counts: five independent
classifiers each emitted one line per ticket — class, the row it read and the evidence the row names —
against a written contract, and the orchestrator re-derived the row and class counts from those lines. Every
candidate in the set above was then re-read in full and each of its rows grounded in an evidence kind this
run produces; a ticket with any row that needs a client, a screen or a person's judgement is not in the
set, however many of its other rows are offline. Those stay in `review/` (§5).

## 4. Verdict rules this batch holds itself to

- A row passes only when this run's own output grounds it: a named test case that this run recorded as
  passed, a gate that this run ran, a build/format/deploy result this run produced, or a committed file
  read in this run. A test that passed in an earlier cycle is not evidence.
- A row whose expectation names a count, a hash or a state from the cycle that wrote the ticket is judged
  by its **durable outcome** — that the suite, the gate or the record the row names still exists and
  passes in this run — and the record's `Limits` says the historical number itself was not re-measured.
- A row that cannot be grounded by this run is `unproven`, and an `unproven` row keeps its ticket open. No
  row is judged by a weaker check than the row states.
- A row is not moved from `review/` to `done/` by a partial judgement: a ticket is accepted only when
  every one of its rows passes.

## 5. Left in `review/`

The remaining tickets in `review/` stay there. The batch's re-derivation covered the 85 tickets that were in
`docs/backlog/review/` when it was planned (64 of them with no acceptance record at all; the tree now holds 65

decide, and every other ticket has at least one row that needs a running client — a captured frame, a live log

screen. They are the input to the session batches, and this run claims nothing about them. The per-ticket
classification this batch used is its own plan artifact; it is not a verdict, and a ticket left here is not
"unproven work in progress" — it is code-complete and waiting for the evidence kind named with it.

## 6. Not part of this run

The delivery checklist (`docs/evidence/delivery-checklist.md`) is **not** reset and **not** filled by this
batch: it is the development cycle's gate, and acceptance is defined to run outside it ("Deployment and
multiplayer acceptance are the agent's actions, run after the commit per `docs/acceptance/` and outside
this gate"). This run changes no `src/`, `tests/` or `tools/` file, and the checklist's items describe a
development sequence this run does not perform. Recording that judgement here is the point — the previous
batch made the same call and left no record of it.

## 7. Exit criteria

- One record per ticket under `docs/evidence/acceptance/`, each naming the batch, the commit under test,
  the deployed artifact identity, one verdict and one evidence pointer per row, and its `Limits`.
- Transition per the verdicts (workflow §8), with the backlog index rows moved in the same change and
  every prose reference to a moved ticket re-pointed, including the gitignored local pages a repository
  search does not reach.
- The gate suite runs green after the moves.
- Lessons fold into `docs/acceptance/lessons.md`; a fact about this machine goes into
  `docs/acceptance/AGENTS.local.md`, never into a committed page.
- An independent adversarial pass reads the frozen tree and this batch's records, and its findings are
  fixed in the same change.
