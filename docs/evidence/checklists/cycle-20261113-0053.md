# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.

- [x] Design comprehension — the root cause read on the release decompile; no design changed — evidence: `Recipe.simpleName` vs `fullName` and the filter line are named on the ticket.
- [x] Native parity — no native behaviour changed; the reading is the game's own filter call — evidence: `PlayerCamera.cs:297` uses `simpleName`; `:304` renders `fullName`.
- [x] Native parity probe — no probe ran this cycle; the next probe is named on the ticket — evidence: the in-scope `__instance`/`value` log line.
- [x] Entry mapping — the entry is the crafting panel's search field, read through `crafting-search` — evidence: `panelActive true, fieldText 'cuiruo', rowCount 0`.
- [x] Mechanism inventory — the patch, the filter line and the locale lookups are named — evidence: the ticket's `## Root cause` section.
- [x] Whole-family audit — both branches (English literal, pinyin) are recorded — evidence: `rowCount` 1 vs 0 with the plugin's own log lines.
- [x] Self-check table — the ticket records both readings and the decompile lines — evidence: `## The reading` and `## Root cause` sections.
- [x] Verification design — one recipe call per branch, judged on `rowCount` — evidence: the suite's `crafting` case covers the crafting entry; this row needs the pinyin branch.
- [x] Plan approved by the user — night mode: the finding is filed with three options and a recommendation — evidence: the ticket's `## Options` section.
- [x] Structure review done — no code changed; the fix belongs to the pinyin mod — evidence: the ticket names the mod's patch file and line range.
- [x] Build + dotnet format + dotnet test normative gates pass — documentation-only cycle — evidence: the previous cycle's gates read 834/0 at `11b12e8f5`.

- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
