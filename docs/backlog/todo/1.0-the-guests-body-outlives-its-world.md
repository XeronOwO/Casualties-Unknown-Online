# The guest's body outlives its world

- Status: Todo
- Priority: High
- Owner: next session
- Found: 2026-11-28, in the 66-row batch (`full-49`).

## Why

About ten of `full-49`'s twenty red rows are one shape: the member's bag is empty or the member cannot be given
anything. `starting-supplies` reads `[]` where the game's plan is `[lantern, dogfood, waterbottle]`; the spectator snack,
the give's trash bag, the crafting material, the two-member marker and `host-crash-restart`'s `the member has no
starting ...` all fail to arrive. Every one of them passes alone.

## The reading

Guest log, 2026-11-28 01:18:24 (during a `world-fingerprint` row, after the row's world guarantee rebuilt the world):

```
[HealReset] local body reset: wasDead=False, restoredLimbs=0, hollowCleared=False, bodyId=-6768
[CarryKernel] rebuilt carry mirror from checkpoint at revision 711
ItemTrace ... origin=OnItemDropped event=Drop
ItemDropped trashbag/lantern/dogfood/waterbottle at (0.3,445.6)/(-1.8,446.5)/(-1.7,446.0)/(-1.4,445.3)
```

The member's starting supplies were dropped at its own feet when the old world was torn down, and the fresh run gave the
member no new ones. The host's row sees its own supplies; the member's bag is empty.

## What the code says

`LocalBodyReset` (`src/CasualtiesUnknownOnline.GameAdapter/Character/LocalBodyReset.cs`) restores limbs and clears
components; it never rebuilds the body or hands out starting supplies. The local body is `PlayerCamera.main.body` and it
survives a world rebuild, so the game's "new character" path — the one that grants starting supplies — never runs for the
member.

## Design

`docs/design/model/item-custody.md` — its custody classes are Body slot, Container, World and In flight, and a body that
survives a world is not a new character. `docs/design/cross-cutting/saves-and-recovery.md` — a restore writes the
character's inventory into the body the receiving client already owns. The game's starting supplies are granted by its own
character-creation path, which is what the member misses here.


## Done when

After a row that rebuilds the world, the member's bag carries the game's own starting supplies (single run and inside the
66-row batch), and the member-item rows that depend on it stop failing on arrival.

## Options

1. Rebuild the member's body when it enters a fresh world, so the game's own character-creation path grants the supplies.
   Product side; the honest fix.
2. Grant the starting supplies from CUO when the member enters a fresh world. Product side, smaller, but it duplicates a
   rule the game owns.
3. Have each row refill the member's bag with `item-provide`. Rejected: it covers the defect instead of fixing it.
