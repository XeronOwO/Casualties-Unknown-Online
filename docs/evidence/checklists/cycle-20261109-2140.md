# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: `docs/backlog/done/save-backups-overwhelm-the-archive.md` gained "The delete surface (2026-11-09)" and the design page `docs/design/surfaces/online-window.md` was updated in the same change
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — `docs/development/native-parity.md` — evidence: n/a, the change mirrors no native action: the game has no world library; the save surface is CUO's own (decision 198)
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: n/a for the same reason
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): the entry is every control of the CUO window — evidence: the two verbs are the panel's own buttons (`worlds.delete_run.<id>`, `worlds.delete_backup.<file>` in `OnlineUiWorldsDrawer.cs`), the only entries to the archive
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: `WorldRepository.DeleteBackup` / `DeleteWorld` (both read and tested), the row indent (`OnlineUiRowModel.Indent` + the adapter spacer at `OnlineUiWindowRowView.SetIndent`), the two-step confirm state (`OnlineUiWindowState.PendingDeleteWorldId` / `PendingDeleteBackupFile`)
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: MECHANISM census: the archive's destructive verbs are delete-backup / delete-world; both are new and both have a guard (last save point; a world in play); no other surface writes the archive
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: the ticket's "The delete surface (2026-11-09)" section (verbs, guards, the tests, the indent rule)
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: focused `SaveArchiveDeleteTests` (5 facts) + the live page reading (delete buttons present, the block indented, the confirmation names the save point)
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: the user's "keep going, the game is about to release, finish the rest in one go" (2026-11-09, translated) after the previous round named exactly these three items
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: `OnlineUiWorldsDrawer.cs` and `WorldLibraryService.cs` stay under 600 lines (checked by the sweep gate); no state bools added (two string fields, empty = none)
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build succeeded; format exit 0; gates 831/0; suite 6637/0
