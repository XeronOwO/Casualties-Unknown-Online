# Delivery checklist

Fill every box, then run `tools/check-delivery.ps1`. Each box needs the literal ` — evidence: ` followed by the evidence.

- [x] Design comprehension — evidence: the batch's model is one guest in the run; a member row left by an earlier case makes every row that addresses "the member" answer with two ids.
- [x] Native parity — evidence: the removal is the product's own `SessionService.KickMember`, not a driver-side edit of the roster.
- [x] Native parity probe — evidence: the quartet read `the run does not have exactly one member: 2` before the guarantee and 4/4 PASS after it.
- [x] Entry mapping — evidence: one entry, the runner's `EnsureLiveWorldAsync`, which every world-case already passes through.
- [x] Mechanism inventory — evidence: the host roster (`state.members`), the driver call path, and the product's kick; the guarantee sits between the roster read and the case.
- [x] Whole-family audit — evidence: the three rows that failed on a two-member roster now pass together with the row that brings the second client in (`two-member-continue`).
- [x] Self-check table — evidence: `.acceptance/shape1` (recipe returned no value) and `.acceptance/shape2` (4 passed, 0 failed) are the readings, and the recipe's missing call parentheses are the fixed defect.
- [x] Verification design — evidence: the quartet run is the verification; the guarantee names each extra id in the timeline and no longer throws over a roster it cannot read.
- [x] Plan approved by the user — evidence: the standing instruction is one run over every case; this is that run's own precondition.
- [x] Structure review done — evidence: the guarantee lives on the session driver next to the world guarantee, not in the thirteen rows that would each need a patch.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build 0, `dotnet format` verify 0, 6749/6749 units, 836/836 gates.
- [ ] Release-cycle deployment/acceptance
