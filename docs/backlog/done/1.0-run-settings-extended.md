- Status: Done — the live 1.0 run carries 50 run-settings keys, including the keys the release
  added (`endless`, `amputee`, `blind`, `crushdepth`, `enemystrength`, `immortalsnail`,
  `insulationmultiplier`, `mindwiped`, `permanentaddiction`, `zeroskills`); the mid-run cut's
  `run.json` carries the same list with the values (`endless` kind bool, `baselootdensity` 1.5,
  `lootmultiplier` 1, `basetrapdensity` 0.349999994 …). The restore reads the same generic list
  (batch `20261108` read the multipliers coming back from a continue), so no per-key code is
  needed. Readings: `docs/evidence/acceptance/1.0-run-settings-20261110-a.md`.
- Priority: High
- Category: Persistence / release
- Source: the 1.0 map (`docs/design/game/ui-and-settings.md`, `docs/design/game/worldgen-and-layers.md`):
  the release adds run settings the demo did not have; CUO's baseline captures the game's own
  `WorldGeneration.runSettings` dictionary wholesale (`HarmonyTraverse.ReadRunSettings`), so the
  question is whether the new keys are in that dictionary and whether the save writes them.

## The question

Do the run settings 1.0 adds reach the host-authoritative baseline and the save's `run.json`?

## Chain (read 2026-11-10)

1. The game's static `WorldGeneration.runSettings` dictionary holds every setting for the run
   (`WorldGeneration.cs:112-114` seeds it from the preset); `GetRunSettingFloat/Bool` read it.
2. `HarmonyTraverse.ReadRunSettings()` (reflection on the static field) → `WorldParamsService`
   (`src/CasualtiesUnknownOnline.GameAdapter/World/WorldParamsService.cs:73`, `:193`) →
   the `WorldParamsMsg` → the kernel `RunState.RunSettings`.
3. The cut writes the kernel's run row to `run.json` (`KernelDomainWireMapper` → the archive);
   a continue reads it back into the kernel and hands it to the game's applier.

## Design

No code change: the path is a dictionary, not a fixed list, so a 1.0-added key is carried the
moment the game's own dictionary holds it. This ticket is the reading that proves it on the
release build.

## Acceptance

1. The live 1.0 run's settings dictionary lists the 1.0-only keys. — read: 50 keys, including the
   ten above.
2. A mid-run cut's `run.json` carries those keys with their values. — read: `endless` (bool),
   `amputee` (bool), `insulationmultiplier`, `enemystrength`, … in the cut
   `w-20261109-d1ec/backups/mid-run-20261109-170614.cuoz`.
3. A continue restores the list. — read by the previous ticket's row (the rarity multipliers
   came back from a continue through the same list; `docs/evidence/acceptance/save-native-run-field-parity-20261108-rows1-3.md`).
