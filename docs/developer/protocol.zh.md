# 协议

[English](protocol.md) | 中文

所有权威信息都以四种信封之一,在一个传输帧里传递。这个帧只承载一个信封,而且信封种类是显式的,
所以接收方可以在解码正文之前就拒绝未知的载荷。

设计目标很窄:客机的操作必须到达主机,主机的决定必须到达每个客机,而落后的客机必须能追上来,
而不必重放整场会话。

## 四种信封

- **Command(指令)** —— 客机的意图,以及主机拒绝某条指令时给出的反馈。
- **CommittedBatch(已提交批次)** —— 一次原子性地被接受的变更,由主机广播给每个客机。
- **Checkpoint(检查点)** —— 完整的状态拷贝,在有人加入、重连或落后太多时按块发送。
- **StateStream(状态流)** —— 位置、瞄准这类高频字段;设计上不可靠,由下一个 tick 或检查点自愈。

## 加入与追赶

加入的客机先收到一份检查点并恢复它,然后应用该检查点之后已提交批次的日志尾巴。如果它发现缺口,
就请求一个区间;如果该区间比主机的日志更旧,主机改为发送一份新的检查点。

## 版本校验

客机加入时双方比对协议版本,号码不一致时任意一方都会结束这次尝试。这个校验就是兼容边界:线路变更
随协议版本号提升一起发布,而不是配一层兼容层,因为不匹配在门口就被拒绝。

## 信封之外的流量

会话与控制、表现、聊天、交易以及模组 API 流量仍然使用各自的帧。它们是单路径协议,而不是第二份权威
存储:其他玩家必须认同的玩法事实属于已提交批次。
