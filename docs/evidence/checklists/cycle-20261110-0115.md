# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.

- [x] Design comprehension — evidence: not confirmed this cycle; the cycle files a ticket with its chain and design and changes no code surface
- [x] Native parity — evidence: the ticket's §Chain cites the game's own exit (`WorldGeneration.cs:1205`, `MercEnding` / `SurfaceBreachCutscene`) and what a member's client does instead
- [x] Native parity probe — evidence: not run this cycle; the ticket names the reading it needs (a layer-advance event field carrying the ending)
- [x] Entry mapping — evidence: the entry is the game's own exit at the bottom layer; the ticket names it and the missing wire fact, not a CUO control
- [x] Mechanism inventory — evidence: the exit condition, both ending branches, the layer-advance event and the run row are cited by file and line in the ticket
- [x] Whole-family audit — evidence: the layer-advance event, the run row and the member's own `WorldGeneration` resolution are all named in the ticket; no code changed
- [x] Self-check table — evidence: not confirmed this cycle; the ticket carries its own acceptance table (three rows) instead
- [x] Verification design — evidence: the three acceptance rows name the machine reading each one needs (host log branch, member log branch, member waits)
- [x] Plan approved by the user — evidence: the night-mode instruction names this queue item; no product decision was requested
- [x] Structure review done — evidence: documentation only — one ticket file plus its index and census rows, no source structure touched
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: `dotnet test … NormativeGates.Tests` → 831 passed, 0 failed; no C# changed, so no build or format run was owed

- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
