# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.
- [ ] Design comprehension — the failure was my wrapper's closing parens (`})())` vs `}))()`), not a cache and not a broken construct
- [ ] Native parity — no game content; the ticket line now names the real cause
- [ ] Native parity probe — the same wrapper on a fresh recipe compiled and ran
- [ ] Entry mapping — one entry, the ticket's bullet
- [ ] Mechanism inventory — the wrapper is copied from the working recipes; the difference was one paren pair
- [ ] Whole-family audit — the two earlier failures shared the defect; both theories are withdrawn in the ticket
- [ ] Self-check table — only the ticket changed this cycle
- [ ] Verification design — the probe's menu answer is the proof of compilation
- [ ] Plan approved by the user — the goal's main line
- [ ] Structure review done — the working probe stays untouched
- [ ] Build + dotnet format + dotnet test normative gates pass — no code change

- [ ] Release-cycle deployment/acceptance: nothing deployed this cycle

- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
