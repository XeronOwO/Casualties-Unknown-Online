## Findings and observations

- The fix held end to end: with the guest out of the world the presentation write no longer reaches the
  host, and with both peers in world the crush still presents on every peer — the air write's
  presentation claim is untouched by the guard change.
- The row-4 echo's symptom and the legitimate placement arbitration share the `[BlockSync] answered …`
  line: attribute by cell AND by the peer's own `presenting a relayed break` line. In this batch the only
  `answered` lines name the crasher's staging placement at the moment it was made.
- The staging substitution does not propagate to the host: the guest's local placement report is refused
  (a placement must land on air) so the host keeps its generated block until the break's air write lands.
  The roll, the report and the presentation under test are unaffected; the host's own crush (the row-4
  half) has no such asymmetry because the host computes that break itself.
- `Item.DMD<Item::Update>` is a NEW anchor for the sandbox NRE family, and it appeared during a world
  re-entry — the window the ticket already names as the cheapest to stage.

## Limits

- One session is not a race proof; every row is read from the state the ends converged to.
- Row 4's evidence is two repetitions in one session, not a frequency measurement: it establishes the
  report's absence for this shape, not that no other write can ever echo.
- The crush staging still rests on the batch-`20261002-b` declared substitution (the shipped world
  cannot generate a health-1 block): the game's own thin-ice id is placed through the game's own
  `SetBlock`, and the native roll, report and presentation run untouched.
- The audible half (does the peer HEAR the break) is a residual for the user; the machine evidence is
  the receiving side's own presentation line.
