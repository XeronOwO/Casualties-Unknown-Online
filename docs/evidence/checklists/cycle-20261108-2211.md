# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: `docs/backlog/review/overlay-buttons-are-silent.md` §The chain (read 2026-11-08) + §The fix.
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — `docs/development/native-parity.md` — evidence: the click is the game's own `PlayerCamera.PlayUISound("click")` (`AdaptiveButton.cs:51/61/65`; `SettingsMenu.cs:192` for "miniClick"), not a CUO sound.
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: not applicable; the sound is local UI audio, no wire and no peer copy.
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): the entry is every control of the CUO window — evidence: `OnlineUiSurfaceHost.ReportIntent` is the single report path every view receives.
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: `OnlineUiControlView.cs` listeners + `OnlineUiSurfaceHost.ReportIntent` + `PlayerCamera.PlayUISound` file:line; the live `sound-log` reading is the acceptance step.
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: buttons/tabs = "click", toggles/dropdowns = "miniClick"; slider/typing/commit stay silent (not clicks); the launcher's own game button unchanged.
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: the ticket's §The fix names the report path, the two sounds and the guards.
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: `sound-log mode=read match=click` on the running client while a CUO button is pressed.
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: the user's defect report and "go ahead, finish it in one pass" (translated).
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: `OnlineUiSurfaceHost` grew one private method; no new state; the two helpers first added to `OnlineUiControlView` were removed when the sound moved to the report path.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build 0/0; gates 831/0; suite 6628/0; `dotnet format` exit 0.


- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
