# 已知问题

[English](known-issues.md) | 中文

本页收集那些被声明出来而不是被藏起来的技术限制:已知尚不能工作的、已知脆弱的,以及每一项记录在
哪里。

只有当一项限制在待办里有了归属、或者有了记录在案的决策之后,它才会出现在这里,所以「已知」意味着
有人负责,而不是有人记得。

## 已声明的缺口

- 本地玩家的客户端预测与回滚没有实现;取而代之的是一次可见的纠正。
- 通用物理同步不在范围内,所以同步集合之外的物理交互可能分叉。
- 反作弊被有意省略:在功能集完成之前,主机信任报告。
- 不支持主机迁移;会话随主机一起结束。
- 有三个内核复制类型仍然留在 Runtime,因为它们的依赖闭包离开了 Application 层。

## 脆弱之处

- Game Adapter 依赖游戏的私有类型,所以游戏更新可能让钩子失效,直到适配器被更新。
- 表现时机(粒子、部分音效)由本地决定,所以两台机器看起来可能略有不同。
- 时机很紧的跨玩家交互是最难的路径,也最可能出现新的缺陷。

## 如何反馈

带上复现步骤、你扮演的角色,如果方便的话再带上两台机器上的日志。`docs/backlog/README.md` 是问题
落地的地方,而交付清单是一次修复在被称作完成之前必须满足的东西。
