# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: `docs/backlog/review/save-backups-overwhelm-the-archive.md` §Design and the 2026-11-08 redesign paragraph; the page's builders were read first (`BuildWorlds`, `BuildWorldRow`, `BuildBackups`).
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — `docs/development/native-parity.md` — evidence: n/a, a window surface.
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: n/a.
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): the entry is every control of the CUO window — evidence: the run row's `worlds.select.*`/`worlds.backups.*` controls, the `worlds.show_older` control, and the folded save points' `worlds.restore.*` controls; the page is reached by `open-window` + `goto-page -Page worlds`.
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: `OnlineUiWorldsDrawer.BuildWorlds` (sort/filter/cap), `BuildWorldRow` (layer text + toggle), `BuildBackups` (inline), `OnlineUiWindowState.WorldsShowAll`, the two catalogue files.
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: the only reader of `worlds.backups_section` was removed with the key (the catalogue gate proved both directions); the other pages' lists are untouched.
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: collapse (the toggle clears `BackupRowsWorldId`; the label flips to Hide) / cap (five newest, `worlds.show_older` for the rest) / layer text (`LayerText` → `worlds.layer_surface` or `worlds.layer_depth`).
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: build 0 errors; gates `passed! (0 failed, 831 passed)`; suite `passed! (0 failed, 6632 passed, net48)`; `dotnet format` exit 0; the live frame after the deploy.
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: the user's directive (2026-11-08, translated: "do it, finish it in one go").
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: `OnlineUiWorldsDrawer.cs` 334 lines (< 600); one state field added; the unused key deleted.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: build 0 errors; gates 831/0; suite 6632/0 (net48); `dotnet format` exit 0.


- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
