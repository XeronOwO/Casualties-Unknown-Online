# Delivery checklist

Fill every box, then run `tools/check-delivery.ps1`. Each box needs the literal ` — evidence: ` followed by the evidence.

- [ ] Design comprehension — the row's claim is that the open remote backpack draws an arriving item through the production refresh, so the red break must remove that call and leave the read intact
- [ ] Native parity — no native chain is mirrored or replaced; the seam skips one production call in an acceptance-only assembly
- [ ] Native parity probe — no probe: the row already reads the native window's slots through the containerUnloadButtons the window rebuilt
- [ ] Entry mapping — one entry: `AcceptancePlugin.Awake` installs the prefix beside the four existing recorders
- [ ] Mechanism inventory — five red seams now exist and each is a case-scoped env switch (A1 arming, A2 backups aside, C1 archive aside, A3 skipped restart, C3 skipped refresh)
- [ ] Whole-family audit — every seam returns the untouched path unless `CUO_ACCEPTANCE_RED` names its case, and a production install never carries the acceptance assembly
- [ ] Self-check table — the red must fail at the arrival assertion and the same case must still pass with the variable unset
- [ ] Verification design — build, units, gates, format, deploy `-Acceptance`, red run, green rerun
- [ ] Plan approved by the user — the night-mode goal authorises self-chosen ticket work without asking
- [ ] Structure review done — the patch is stateless, finds its target by name (no product reference), and logs when the target is missing instead of silently passing
- [ ] Build + dotnet format + dotnet test normative gates pass
- [ ] Release-cycle deployment/acceptance
