- Status: Done
- Priority: High

## Why

The batch's `character-solo-lock` row failed while its single run passed (31.2 s, `solo-1`).
The host log for the batch run (`full-50`, 66 rows, 1,629 s) carries **3,401**
`[Unity:Exception] NullReferenceException` lines, every one from
`TechballScript.Update ()`; they start at 03:52:15.706, right after the row's
leave. The techball was created by our own spawn channel at 03:52:04.631 and
again at 03:52:15.696 (`[EntitySpawn] created techball at (54.00, -35.00)`,
creation `3247505181454926391:3368110122/…123`); it is still alive after the
world is torn down, so the menu scene counts a live `BuildingEntity` whose
`Update` runs against a world that no longer exists.

The row reads the host's solo picker after the leave; the per-frame exception
storm is the only new input the batch adds, and the single run (fresh process,
no earlier world) has none.

The spawn at 03:52:15.696 is the continue's world rebuild, not a leftover: the
techball is created in the window where the rebuilt world's tables are still
empty (`[TrapLayout] live-scene refresh REFUSED (0 scanned)`,
`[BlockDamageSnapshot] no live world`, `[Crafting] no live recipe table` all
log in the same three milliseconds), and its `Update` then runs against those
empty tables for 3,401 frames.

## What we read

- `src/CasualtiesUnknownOnline.GameAdapter/World/EntitySpawnSync.cs` stamps
  every runtime creation with `RuntimeEntityCreation.Stamp` and tracks death
  through `OnRuntimeEntityDestroyed`; nothing walks the stamped set on leave.
- `src/CasualtiesUnknownOnline.GameAdapter/Patches/PlayerCameraMenuExitPatches.cs`
  defers the menu load for the seam but owns no entity cleanup.

## Options

1. **Destroy the stamped runtime entities when the world is left** (product).
   The creation marker already identifies them; the adapter knows when the seam
   performs the leave. Cost: one sweep at the leave edge, no row change.
   Recommended.
2. Sweep them from the acceptance suite after each leave (test-only). Cheaper,
   but the same leak hits real players who leave a world mid-run.
3. Record the debt and leave the NRE storm: rejected — it fails a row whose
   single run is green, and 3,401 exceptions per leave are not a measurement.

## Done when

A batch run's `character-solo-lock` passes with no `TechballScript.Update`
NullReferenceException in the host log after the row's leave, and no runtime
entity created by `EntitySpawnSync` survives its world.
