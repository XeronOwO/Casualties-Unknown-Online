## What the player sees

Two friends join a host's run. The host saves and continues. One friend keeps the character and items they had;
the other comes back as a fresh character with the starting supplies, and the first friend's bag may gain the
second friend's items.

## Design

The behaviour is the one `docs/design/cross-cutting/saves-and-recovery.md` states: a cut names what the live world
has, a continue restores it, and each present member's character is handed over before the entry instruction; the
peer/transport keying rule it relies on is described in `docs/architecture/session-continuity.md` ("an in-world peer
the run affects must be re-keyed or re-instructed before it reads the new run id"). The domain's own surfaces are
`docs/design/model/session-lifecycle.md` (a host may open the room over the world it continued) and
`docs/design/cross-cutting/observability.md` (the reading above is a log fact, not a guess).

   read whether the second peer is in that set at the continue's world-entry edge.
