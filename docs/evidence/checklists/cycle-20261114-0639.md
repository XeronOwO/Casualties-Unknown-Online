# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.
- [x] Design comprehension — the leave wait runs in the client that owns the world, not in a caller poll — evidence: `wait-state` gained `notInWorld`, the two leave paths call it
- [x] Native parity — the driver reads `IWorldPresenceQuery` in-process — evidence: the driver block
- [x] Native parity probe — the suite's own leave paths used the new wait — evidence: the full run's cases that leave (role-clearing, remote-removal) passed
- [x] Entry mapping — two call sites replaced, one helper — evidence: the diff
- [x] Mechanism inventory — the budget stays at 20 s under the 30 s eval timeout — evidence: the converted lines
- [x] Whole-family audit — `inWorld` and `notInWorld` are the only predicates the driver answers; the rest still poll — evidence: the block
- [x] Self-check table — one tooling + one test file — evidence: `git status --porcelain`
- [x] Verification design — the full suite is the judge — evidence: 30 passed / 1 failed, and the single failure is the filed heal intermittent (it passed alone at 06:40)
- [x] Plan approved by the user — the goal's main line (event-driven) — evidence: the goal's 2026-11-14 paragraph
- [x] Structure review done — a named helper, no inline lambda duplication — evidence: the diff
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: the suite build answered 0 errors at 06:30; tests unchanged

- [ ] Release-cycle deployment/acceptance: nothing deployed this cycle

- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
