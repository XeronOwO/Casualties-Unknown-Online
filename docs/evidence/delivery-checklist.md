Fill every box, then run `tools/check-delivery.ps1`. Each box needs the literal ` — evidence: ` followed by the evidence.

- [ ] Design comprehension — the row's claim is that an item arriving in the owner's backpack reaches a member's already-open window; the per-snapshot entry that draws the clone's container children is ApplyCloneInventory
- [ ] Native parity — no native chain is mirrored or replaced; the seam drops later applications in an acceptance-only assembly and keeps the first ones until the clone's container holds drawn children
- [ ] Native parity probe — no probe: the row reads the native window's own slot buttons through `containerUnloadButtons`, not the clone body
- [ ] Entry mapping — one entry: `AcceptancePlugin.Awake` installs the prefix beside the recorders
- [ ] Mechanism inventory — five red seams exist and each is a case-scoped env switch (A1 arming, A2 backups aside, C1 archive aside, A3 skipped restart, C3 dropped later applications)
- [ ] Whole-family audit — every seam returns the untouched path unless `CUO_ACCEPTANCE_RED` names its case; the C3 guard had to name the drawn container, not the drawn clone, because a clone's slot items exist before its backpack container does
- [ ] Self-check table — the red must fail at the arriving slot, and the same case must pass with the variable unset
- [ ] Verification design — build, units, gates, format, deploy `-Acceptance`, red run, green rerun
- [ ] Plan approved by the user — the night-mode goal authorises self-chosen ticket work without asking
- [ ] Structure review done — the patch is stateless, finds its target by name (no product reference), logs through BepInEx when it arms and once when it suppresses, and warns instead of passing silently when the target is missing
- [ ] Build + dotnet format + dotnet test normative gates pass
