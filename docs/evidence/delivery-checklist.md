# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle.

- [ ] Design comprehension — the nested drive branch was read before the change
- [ ] Native parity — the nested coroutine name is the game own type
- [ ] Native parity probe — the world size and chip facts were identical
- [ ] Entry mapping — the log brackets every nested drive
- [ ] Mechanism inventory — the window between segments is the only unexplained consumer
- [ ] Whole-family audit — two log lines, no behaviour change
- [ ] Self-check table — diagnostics only
- [ ] Verification design — the next failing run shows which nested drive moved the stream
- [ ] Plan approved by the user — root cause first
- [ ] Structure review done — the probe stays in the isolation
- [ ] Build + dotnet format + dotnet test normative gates pass

- [ ] Release-cycle deployment/acceptance: deploy and read the nested lines on a failing run

- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
