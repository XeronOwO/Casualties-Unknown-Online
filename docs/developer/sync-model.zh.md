# 同步模型

[English](sync-model.md) | 中文

CUO 为世界保留一份权威状态,以及它的许多画面。主机拥有那份权威状态,每台客机决定自己的玩家在做
什么,而主机仲裁那些不可能同时成立的声明之间的冲突。

这个模型是为了让会话在普通网络下也能玩:一个必须先往返、玩家才能行动的决定会让游戏感觉坏掉,所以
尽量少的事情去等往返。

## 谁决定什么

- **发起操作的客机**依据自己的画面与自己的时间,决定自己的玩家做什么。
- **主机**拥有权威状态、已提交变更的顺序,以及冲突的仲裁权。
- **每一侧**都应用主机提交的结果,于是所有画面收敛到同样的事实。
- **表现**由本地决定:粒子、部分音效与动画时机并不同步。

## 冲突仲裁

当两份声明不可能同时成立时 —— 同一件物品被两人拾取,同一个容器被两人清空 —— 主机接受它先收到的
那一份,并用带类型的理由拒绝另一份。被拒绝的一方会知道它为什么失败,而不是操作被悄悄吞掉。

## 纠正

与已提交状态不一致的画面会被纠正,而且纠正是可见的。模组绝不让两台机器悄悄分叉,因为未被发现的
分叉在诊断上的代价远高于一次可见的拉回。

## 有意不做的事

这里没有对其他玩家的客户端预测,没有本地玩家的回滚,也没有反作弊:每一项都是各有代价的独立设计,
而 CUO 今天面向的合作玩法并不需要它们中的任何一个。
