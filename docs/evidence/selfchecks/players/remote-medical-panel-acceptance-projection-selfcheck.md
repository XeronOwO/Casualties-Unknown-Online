# Remote medical panel acceptance projection self-check

Owner cycle: `docs/backlog/todo/remote-medical-panel-acceptance-issues.md`.

## 1. Problem

User acceptance (2026-09-06) found three remote WoundView issues:

1. Fentanyl mood/happiness advanced only at the 1 Hz character snapshot cadence.
2. A stopped-remote-breathing state showed the generic `hypoventilation` icon
   instead of the critical `cantbreathe` icon.
3. The remote WoundView ECG still drew the viewer's own heart (and kept beating
   after the viewed player's heart stopped).

## 2. Root cause

The remote WoundView display body is deliberately inactive, so the native
`Body.Update`, `Painkillers.Update` and `Antidepressants.Update` passes never
run on it. Several fields the native panel/moodle manager reads directly are
therefore left at template defaults or stale 1 Hz values:

- `Body.breathing` is recomputed every frame by `Body.Update`
  (`Body.cs:2770`) and is never on the wire.
- `Body.respiratoryRateReadout` is generated by the live circulation pass
  (`Body.cs:931`) and is never on the wire.
- `Body.heartProg` is advanced by the live body (`Body.cs:888-906`) and drives
  the ECG waveform shape.
- Opiate happiness follows `Painkillers.Update`'s 5-units/sec ramp toward
  `opiateAmount - opiateTolerance`; the real-time medical operation state
  carries the newly committed `OpiateAmount` many times per second, while
  `ActualOpiateReception` is still only the last 1 Hz body sample.

The existing `ECGVisualizer.get_body` patch was a Harmony **Prefix** that set
`ref __result` without skipping the native getter; the native getter then
overwrote the redirect, so the panel ECG stayed on the viewer's own body.

## 3. Changes

- New `RemoteMedicalDisplayProjection`: pure projection rules for the inactive
  display body.
  - `ProjectBreathing`: `Alive && RespiratoryRate > 10`, matching `Body.cs:2770`.
  - `ProjectRespiratoryRateReadout`: `Round(RespiratoryRate * 0.25) + "/m"`,
    matching `Body.cs:931`.
  - `AdvanceOpiateReception`: native 5-units/sec `MoveTowards` toward
    `OpiateAmount - OpiateTolerance`; immediate zero when both opiate amount
    and tolerance are zero.
  - `OpiateHappinessFromReception` / `ToActualReception`: native positive and
    negative conversion, with the documented clamp approximation for the
    deepest negative range.
  - `AdvanceHeartProgress`: native heart progress wrap, and zero at
    `heartRate <= 0`.
- `RemoteMedicalCoordinator`:
  - Applies the breathing and respiratory readout projections.
  - Advances the ECG heart progress every frame.
  - Carries the raw opiate actual in `Body.opiateHappiness` and re-writes the
    projected actual onto the display `Painkillers` component every frame, so
    the native moodle manager's overdose/withdrawal row still reads the
    display body instead of the viewer.
- `RemoteMedicalPatches`:
  - `ECGVisualizer.get_body` changed from Prefix to Postfix, so the redirect
    actually replaces the native getter result.
  - The redirect excludes only `PlayerCamera.main.consciousnessECG` (the
    viewer's own consciousness overlay); all other remote medical ECG surfaces
    (WoundView, remote manual-defibrillator minigame) read the display body.

## 4. Verification

- Regression tests: `RemoteMedicalDisplayProjectionTests` (10 cases). The
  pre-fix run failed because the projection type did not exist / the code still
  followed stale 1 Hz values; post-fix run passes.
- `dotnet build CasualtiesUnknownOnline.slnx`: 0 warnings / 0 errors.
- `dotnet format CasualtiesUnknownOnline.slnx`: clean.
- `dotnet test CasualtiesUnknownOnline.slnx`: 2498 tests + 17 normative gates
  pass.
- Two independent adversarial reviews were run; the second found the opiate
  ramp needed to mirror native (raw actual state, downward decay, all-zero
  clear, keep Painkillers component visible for native moodles), which was then
  implemented and re-verified.

## 5. Known boundaries

- The deepest negative opiate clamp is stored through `Body.opiateHappiness`,
  so `ToActualReception(-80)` is approximate (-48.19). It does not affect the
  reported fentanyl/positive-dose acceptance issues; negative withdrawal
  terminal fidelity remains approximate in the display projection.
- `randomFibrillationVariation` and `defibShockedFrames` are not yet carried for
  the display-only ECG; they are low-priority adjacent presentation fields and
  are not part of the three reported acceptance issues.
