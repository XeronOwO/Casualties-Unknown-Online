# 1.0 regression — batch 1: the remote medical panel

- Batch: 1 (medical view and panel), first half.
- Build: the release install (`Casualties Unknown`, app id 4576490), deployed from this tree.
- Session: the desktop host and the Steam1 box, offline IP direct (no Steam in the box), one world.
- Ticket: `docs/backlog/in-progress/1.0-regression-sweep.md` (the sweep this batch belongs to).

## Fixture

The host opened the member's chart through the acceptance channel (`medical-open`), the same call the
Online UI's member row makes. The member id is the one the HOST sees: over IP direct it is the
session's logical id (`13486974461430123824`), not the box account's Steam id — `medical-open` with
the Steam id answered `opened:false` and the coordinator logged `[MedicalView] refused open for …
not in-world`, with `isRemoteInWorld:false` for that id. The panel's readings are the adapter's own
`RemoteMedicalView` state, not a picture of the panel.

## What this batch confirms

The remote chart is the release build's own wound view driven by the adapter, the read-only promise
holds (no nap, no workout, no hand switch), the header belongs to the viewed player, and the alarm
reads the displayed body's heart rather than the viewer's.

## Limits

- The injection (fentanyl), the treatments (bandage, tourniquet, splint), the CPR controls and the
  shrapnel session are batch 1's second half; they are not read here.
- The panel's visible typography is not judged (a picture of the panel is not the row; the row is
  the state above).
- The IP-direct member id differs from the Steam id by transport; the fixture now uses the host's
  session facts, and the Steam path keeps its own id. This is a fixture fact, not a defect.
