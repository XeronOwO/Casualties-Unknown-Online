# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.
- [x] Design comprehension — the heal reset's write path is the ticket's subject, not this cycle — evidence: the appended section names the next probe
- [x] Native parity — the probe reads the game's own log and limb state — evidence: the failing report's readings
- [x] Native parity probe — the reset applies while the limb reads hurt — evidence: the boxed log line against `skinHealth 0.344`
- [x] Entry mapping — one ticket section added — evidence: the diff
- [x] Mechanism inventory — the failure rate and both readings recorded — evidence: 2 of 7 runs
- [x] Whole-family audit — the same file keeps its earlier readings — evidence: `git diff`
- [x] Self-check table — documentation only — evidence: `git status --porcelain`
- [x] Verification design — the next cycle's probe is named — evidence: the appended section
- [x] Plan approved by the user — the goal's main line — evidence: the goal's 2026-11-14 paragraph
- [x] Structure review done — the section lives on the ticket it judges — evidence: the diff
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: documentation-only cycle; no code touched

- [ ] Release-cycle deployment/acceptance: nothing deployed this cycle

- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
