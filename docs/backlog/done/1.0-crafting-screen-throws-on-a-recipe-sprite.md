# 1.0: the crafting screen cannot open — a recipe's product sprite throws

- Status: Done — the root cause was OURS, not the game's: the product id was `example.dressing`, a
  recipe the deployed example mod declares, and its item has no game prefab, so the game's own getter
  threw while drawing the list. The vanilla game (the mod layer disabled) opens the crafting screen
  normally (measured 2026-11-14). The framework now answers a placeholder for a recipe whose product
  has no prefab (`RecipeSpriteFallbackPatch`, Crafting capability): on `0.1.0+0e5ee8292` the craft key
  opened the panel (`panelActive: true`), the log carried one `[Recipe] example.dressing has no prefab
  to draw` line, and there was no `NullReferenceException`.
- Priority: High
- Created: 2026-11-13

## The root cause, corrected (2026-11-14)

The earlier reading blamed the game's content. It was ours: `grep example.dressing` finds the id only
in `src/CasualtiesUnknownOnline.ModExample`, which ships with the install. The chain is the game's:

- the craft key (`PlayerCamera.cs:1022`) → `OpenCraftScreen()` (`PlayerCamera.cs:192`) →
  `RefreshRecipeList()` (`PlayerCamera.cs:266-288`) → for each row `Recipe.resultSprite`
  (`Recipe.cs:10-20`) → `Resources.Load<GameObject>(result.id)` → null for our item →
  `GetComponent<SpriteRenderer>()` throws, the list aborts, the screen never opens.

The game's own recipes all have prefabs, so the branch only a mod's custom item reaches. The framework
owns content registration, so it now guarantees the screen: `RecipeSpriteFallbackPatch` answers a cached
placeholder and logs the id once; liquids and every game recipe take the native branch.

## What the player sees

The craft key does nothing on the 1.0 release: the panel stays closed, and the mod log carries a
`NullReferenceException` from the game's own recipe refresh.

## The mechanism (read in the decompiled 1.0 source)

`reversing/release-1.0/Assembly-CSharp/Recipe.cs:10-20`:

- a liquid result reads `Liquids.Registry[this.result.id].color` (a missing id throws a key error);
- any other result reads `Resources.Load<GameObject>(this.result.id).GetComponent<SpriteRenderer>().sprite`.

A recipe whose `result.id` has no loadable prefab makes `Resources.Load` return null and the
`GetComponent` throws — an NRE at the getter's `[0x47]`, exactly the frame in the reading. The refresh
iterates every visible recipe, so one such recipe closes the door for the whole panel.

## The recipe named (2026-11-13, the same session)

`crafting-panel mode=probe` walks the game's own static `Recipes.recipes` and reads each recipe's own
`resultSprite` inside a try. On the deployed build: `checked 138, badCount 1, badIds ['example.dressing|NullReferenceException']`
— exactly one recipe's product cannot be loaded, and it is the one the panel's refresh walks into. The
crafting panel is therefore unreachable on the 1.0 build for every player, not only in the fixture.

## The fix (options and a recommendation)

- **A. Guard the getter in CUO.** A Harmony prefix on `Recipe.resultSprite` returns a placeholder sprite and
  one warning line when the product cannot be loaded, so the panel opens and the row reads as a blank
  product. Small, defensive, and it names the recipe in the log every time.
- **B. Leave it.** The defect is the game's content (a recipe whose product prefab is absent in 1.0); a later
  game update may fix it, and CUO stays out of the crafting UI.

**Recommendation: A**, because every crafting row in the sweep goes through this panel and the recursion mod
renders inside it; a placeholder row keeps the surface usable while the log names the broken content for a
future game update. The decision changes how far CUO reaches into the game's own UI, so it is written here
for the user rather than taken alone.

## Next probe

Enumerate `Recipes.recipes` (the static list) in one evaluator call, call `resultSprite` on each entry
inside its own try, and report the first id that throws (plus how many recipes throw). That names the
recipe, and then the row is either a CUO fix (skip the bad row like the game does elsewhere) or a game
content defect written onto the ticket with the id.
