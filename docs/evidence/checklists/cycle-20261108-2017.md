# Delivery Checklist

Every development cycle runs through this checklist, validated by `tools/check-delivery.ps1` before the cycle's commit.
The script refuses a commit while a required box is unchecked or carries no evidence, archives the cycle's record under
`docs/evidence/checklists/`, and resets every box. A box is checked only after the item was CONFIRMED done in this cycle:
the suffix records an observation. Documentation-only cycles fill every box in one pass and may skip `dotnet format`;
the focused normative-gate run is not optional. Deployment and multiplayer acceptance run after the commit.

- [x] Design comprehension — before the first code edit the ticket states, in its own section, the surface being changed — evidence: the three tickets carry their reports and the chain to read (`overlay-buttons-are-silent.md`, `save-backups-overwhelm-the-archive.md`, `native-console-is-unpoliced.md`).
- [x] Native parity — the three lines (player's action and expectation / the native chain the game itself runs / how the clone reproduces it) — `docs/development/native-parity.md` — evidence: the native console ticket names `ConsoleScript` and the character-sync trust boundary; the UI-sound ticket names the game's own click path.
- [x] Native parity probe — for a behaviour that mirrors a native action, the SAME action was run locally and across clients — evidence: no code changed this cycle; the console ticket's reproduction is the user's own (Steam2 `heal`).
- [x] Entry mapping (a scope that crosses players or mirrors a native action only): no player gesture changed; the entry is the console verb's own line — evidence: no player-facing entry touched.
- [x] Mechanism inventory: every touched mechanism has evidence (decompiled file:line or runtime log) or is explicitly marked unverified — evidence: the tickets name `ConsoleScript`, `CharacterDataSync`, `CheatAdminCommands`, `OnlineUiHost`, the save repository.
- [x] Whole-family audit: fixing one mechanism, the whole family was aligned one by one (no piecemeal fixes — the turret-fire/geyser lesson) — evidence: ticket 3 names the full native-console command family (heal, kill, give, spawn, setcondition, item and block commands) as the scope.
- [x] Self-check table: mechanism x change x evidence, every cell filled — evidence: no code change; the acceptance rows are written into each ticket.
- [x] Verification design: how the runtime proves it (diagnostic traces, peer log comparison, hotrepl assertions) is decided — evidence: each ticket states its acceptance readings.
- [x] Plan approved by the user (before deployment; investigation excepted) — evidence: the user filed the three items (2026-11-08).
- [x] Structure review done (touched classes <= 600 lines OR the size is recorded in docs/architecture-debt.json with its split plan; state bools; dead mechanisms deleted in the same round) — evidence: no `src/` change.
- [x] Build + dotnet format + dotnet test normative gates pass — evidence: no compiled C# changed; gates will run in the next cycle that edits code.


- [ ] Release-cycle deployment/acceptance: run by the agent after the commit
      (build → deploy → two-client acceptance per `docs/acceptance/`), outside the
      development commit gate; simulation/static evidence is the feature development
      verification standard.
- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
