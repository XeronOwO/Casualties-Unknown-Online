# 文档编写规范

[文档总览](../README.md) > [贡献者文档](README.md) > 文档编写规范

---

**读完这一页**，你能给这套文档加一页、让另一种语言的那一侧同步跟上，并知道哪些部分由门禁（gate）把着。
绑定规则写在 [`../../AGENTS.md`](../../AGENTS.md) 里——agent 进入 `docs/` 时会自动加载它；本页是写给人看的说明。

## 两棵树，同一套页面

- `docs/en/` 是英文，`docs/zh/` 是中文。目录、文件名、页面集合完全一致：增、删、改名、移动，都必须在中英两侧同一次改动里完成。
- 每棵树内部分为 `start/`（入门，按顺序读）、`how-to/`（一件事一页）、`internals/`（为什么这样设计）、
  `reference/`（查阅：接口、协议、配置、矩阵、术语）和 `contributing/`（构建、门禁、复核（review）、本规范）。
- `docs/standard/` 放这套文档自身依赖的登记表：术语表与配对对齐记录。代码和门禁读取的机器基线与表格放在
  [`docs/contracts/`](../../contracts/README.md)——`Abstractions` 基线加两张特性矩阵——而 `docs/evidence/`
  下的那些 JSON 基线仍留在被描述对象的旁边。
- 一份文档是一个层次，不只是文件：agent 文档（如 `AGENTS.md`）回答“这活怎么做”，只有英文；
  人类页面回答“这个产品是什么”，中英成对。
- 流程记录（`docs/backlog/`、`docs/evidence/`、`docs/decisions/` 以及各周期的日志）保持英文、留在原路径、不进人类导航；
  它们的结论会被吸收进正文，记录本身不翻译。
- 每个目录都有 `README.md` 作为人类索引。`AGENTS.md` 只出现在交界处（`docs/`、`docs/en/`、`docs/zh/`、`src/`、`tests/`、`tools/`），
  它负责指路而不是讲知识，并且必须待在自己的字节上限之内。

## 一页长什么样

一页只回答一个问题，标题说清读者读完能做什么：

头部面包屑（breadcrumb） → 分隔线 → 一句话目的（“**读完这一页**……”） → 难度与前置 → 步骤 → 能跑的例子 → 为什么这样设计 →
常见坑 → 怎么验证成功 → `相关阅读`（3 到 6 条）→ 分隔线 → 尾部面包屑。

`start/` 的页面只讲那条能走通的路，讲完就停；细节属于 `how-to/` 或 `internals/`，用链接指过去，不复制一遍。
索引页是例外：它列出本节页面，开头写明自己所在的路径（如 `docs/zh/how-to/`），首尾同样带面包屑与分隔线（指向它上面那一层入口），但不要求写`相关阅读`。

## 语言

- 英文页写给英文读者，中文页写给中文读者：事实相同，中文自然，不是逐句翻译。
- 项目特有词按 [`../../standard/terminology.txt`](../../standard/terminology.txt) 登记的写法写；
  新词在第一次使用之前先登记进去，这样同一个机制不会在两页里出现两种译名。生造词、生硬直译、不解释的行话都算缺陷，不算风格。
- 只提交进会话、不进仓库的交流，按项目主人自己的偏好来，偏好记在进不了 git 的 `AGENTS.local.md` 里。
- 语言切换链接只出现在三个入口页：[`../../README.md`](../../README.md)、
  [`../../en/README.md`](../../en/README.md)、[`../README.md`](../README.md)——也就是 `docs/README.md`、
  `docs/en/README.md`、`docs/zh/README.md`。子页面靠面包屑导航，自己不写切换链接。
- 旧式“兄弟文件”形态（`foo.zh.md`、`foo.i18n.yaml`）已经退役：一配对就是路径镜像，`docs/` 下面任何地方都不许再新增这种文件。库里已无这种产物，这条靠复核守住。
- 中文正文用中文标点：`，。、；：？！`、中文引号与全角括号；ASCII 标点只留在代码、路径、标识符，以及英文专名或英文短语里（如 `Casualties Unknown: Online`）。门禁只拦最直白的一种：两个汉字之间的 ASCII 标点；其余靠复核。

## 链接

- 一律用相对链接，并且要能指到真实存在的文件：门禁会遍历两棵树里每一条 markdown 链接的目标。
- 头部面包屑放在开头几行，首尾两条面包屑都写出真实路径，例如“文档总览 > 做一件事 > 给其他玩家发消息”，
  并链接到本语言块的总览页（`docs/zh/README.md`）与所在分区的索引。
- 正文页结尾放 3 到 6 条`相关阅读`：读者接下来最可能需要的东西；索引页不必写。
- 项目特有词在一页里第一次出现时，链到[术语表](../reference/glossary.md)。

## 真实性

- 命令、输出和代码片段都来自真实运行，不凭记忆写。
- 关于我们自己代码的论断，引路径加原文引用，绝不写行号——行号会被它上面任何一次编辑顶掉。
  反编译树 `reversing/` 可以带行号，因为那棵树从不编辑。
- 只有真实双客户端会话才能确认的行为，要标明“等待用户实机验收”。测试全绿不是那种证据。

## 新增一页的步骤

1. 在同一次改动里，把英文页和中文页写到镜像路径上。
2. 在两棵树的分区索引里都加上链接；如果是新分区，还要更新 `docs/README.md`。
3. 有新项目词就登记进 `docs/standard/terminology.txt`，并补进两棵术语表。
4. 把这一对登记进 [`../../standard/alignment.txt`](../../standard/alignment.txt)：两个路径加两个 git blob 哈希，
   哈希用 `git hash-object <文件>` 取得。这份记录是内容比对——任何一侧被编辑，两侧哈希都要重新登记。
5. 提交前跑文档门禁（见下）。

## 门禁查什么，查不了什么

`DocumentationTreeGateTests` 查两棵树的路径配对、每个相对链接是否指向真实存在的文件、上面的页面形状，
以及每一对是否按当前内容登记在册。`AgentInstructionBudgetGateTests` 保证每个嵌套 `AGENTS.md` 不超过 5 120 字节，
并让整条指令链（根目录、`docs/AGENTS.md`、两棵树的文件、本机文件）待在共享的 65 536 字节加载预算之内。

门禁只能证明“存在且形状正确”。它判断不了一页有没有把人教会、译文自不自然、论断是不是真的；
这些仍然是复核的职责，对照术语表来查。

## 防漂移

- 动了一侧就必须在同一次改动里动另一侧；忘了的时候，对齐记录会报出漂移。
- 保留提炼过的结论——决策、规则到门禁的映射、清单、自查记录。流程日志的结论一旦被吸收、入站链接也改完了，就删掉它：
  删，不要归档。git 留着历史，而归档会招来过期阅读。

## 怎么确认成了

- `dotnet test tests/CasualtiesUnknownOnline.NormativeGates.Tests --filter "FullyQualifiedName~DocumentationTree"` 全绿，
  指令预算门禁同样全绿。
- 一对页面在镜像路径上都存在、都被列进分区索引，`alignment.txt` 里的两个哈希都和磁盘上的文件一致。
- 中文读者读中文页就能拿到同样的事实，不需要对照英文句子。
