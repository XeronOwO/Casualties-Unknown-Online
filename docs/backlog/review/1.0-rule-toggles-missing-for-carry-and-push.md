# Push, carry and piggyback have no host switch

The mechanics exist: `PlayerPushService` commits a push from the pusher's Strength, and
`CarriagePatchBridge` carries a body's carry relation onto the clone. The rule surface only carries
`PiggybackWeightMultiplier`; there is no switch to allow or forbid pushes, no "always allow carry",
and no piggyback stack limit. A host who does not want to be shoved has no setting.

## Design

The permission surface (`docs/design/cross-cutting/permissions-and-commands.md`) and the body-action
families (`docs/design/game/README.md` — the body's own interactions). These are host rules, so they
belong to `IHostRules`/`HostRuleSet`, announced like every other rule, and read by behaviour on both
sides rather than by the UI alone.

## The reading (2026-11-14, release build)

`grep 'AllowPush|AlwaysAllowCarry|PiggybackMax' src/` finds nothing; `HostRuleSet` carries
`PiggybackWeightMultiplier` and nine other flags but none of these three. The reference mod ships all
three as host rules.

## Acceptance rows

1. With pushes off, a push attempt is refused on the pusher's own client with a named reason, and the
   target's body does not move.
2. With "always allow carry" on, a carry that the game would refuse (an unconscious carrier rule)
   succeeds and the clone follows.
3. The piggyback stack limit refuses the N+1st body on the operator's own client, and the value is
   announced to members.
