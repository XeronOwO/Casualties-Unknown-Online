# Delivery checklist

Operating rule: a box is checked only after the item is CONFIRMED in this cycle. Bulk checking is forbidden — a box
that cannot be confirmed stays empty and the cycle stops. Documentation-only cycles fill every box in one pass and
leave the release-cycle deployment/acceptance line and the FORBIDDEN line unchecked.
- [ ] Design comprehension — the domain pages were read before the claim
- [ ] Native parity — the recorder's new field reads the game's own body transform
- [ ] Native parity probe — the body position is the remaining root-cause variable named on the ticket
- [ ] Entry mapping — the resync ticket names entry, break, placement and the missing reconcile
- [ ] Mechanism inventory — the game's 128-cell table bounds the reconcile payload
- [ ] Whole-family audit — both directions (member→host, host→member) are covered
- [ ] Self-check table — the recorder change is one line plus one guard; the ticket is documentation
- [ ] Verification design — the recorder reads on the next pair run; the ticket carries four acceptance rows
- [ ] Plan approved by the user — add the reconcile, optimized; keep deterministic generation as the root fix
- [ ] Structure review done — the recorder stays acceptance-only; the reconcile is a backstop, never a replacement
- [ ] Build + dotnet format + dotnet test normative gates pass

- [ ] Release-cycle deployment/acceptance: no deploy in this cycle

- [ ] FORBIDDEN — never check this box; checking it fails the delivery gate
      (a honey-pot: a checked box means a step was skipped on purpose, which is
      exactly what the gate exists to catch)
